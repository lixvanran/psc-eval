## 三、★★ 上界报警的真正含义：不是过拟合，是「同义反复」

```
upper_alarm = True（F1 0.8544 > 开卷天花板 0.7664）
```

**这个报警不是「抽取器过拟合」，也不是「金标泄漏」。真正的含义是**：

> **金标与抽取器共享同一套规则。**
> 金标是**按这套规则人工构造**的，抽取器也是**按这套规则**判的
> ⟹ **抽取器按规则判 ≡ 金标按规则判 ⟹ 高一致性是同义反复。**

**⟹ 这把尺子的主指标（F1）实际测的是「规则执行的一致性」，
而不是「域外方向的发现能力」。**

**这与 ㉑-b / ㉕-b 完全咬合**：
- 「发现失败」在闭卷下**不可度量**（三面围堵：违反禁区 / 标注者主观 / 被候选集措辞遮蔽）
- 主指标 F1 反映的又是**规则执行**（发现 + 保留/否决分布）
- ⟹ **尺子测不到「发现能力」，而那恰恰是「问题空间构建」最核心的一项**

**这不是这把尺子的缺陷，是「域外方向」框架 + 人工构造金标的结构性后果。**

**⟹ 必须与 M3 的 PRP 探针（前提识别能力）并列呈现** —— **PRP 测的才是「发现能力」这一维。**

**报告必须写明的普适结论**：

> **任何用「人按规则造金标 + 模型按同一规则判」方式做的评测，
> 其分数上界是「规则执行一致性」，而非能力本身。**
> **换一把规则、换一批题、换一个模型，都能复现这个高一致性 —— 所以它不构成能力证据。**

## 四、★ 方法论：这把尺子是怎么被造出来的

### 4.1 七次「假通过」（七次「结论看起来正常但其实错了」）

| # | 症状 | 层 | 失败方向 |
|---|---|---|---|
| ⑯-b | `fp` 逐条覆盖 | 计算层 | 报得比实际好 |
| ⑰-e | 旧 CSV 继承错值 | 数据层 | 污染下游 |
| ⑳-a | 池口径不一致 | 口径层 | 量的不是同一个东西 |
| ㉓-c | 分支永不进入 | 枚举层 | 那段逻辑从未被执行 |
| ㉖-a | 循环论证的断言 | 断言层 | 参照物 = 被断言对象 |
| ㉘-b | 「抽取器过宽」（主会话判断） | **判断层** | 实为规则与金标不一致 |
| ㉙-a | 「泄漏导致方向错乱」（主会话判断） | **判断层** | 实为立场错判，分片间方向相反 |

**通则**：

> **① 汇总量（delta / 差值 / 比例）只能定位「哪儿有差异」，不能定位「谁错了」。方向性归因必须逐条核。**
> **② 凡结论依赖「分片间方向一致」这个前提，必须在全部分片上验证，并给出逐分片的数。**
> **③ 不报错 ≠ 算对了。** 本项目至今所有最贵的错误都长成「结果看起来完全正常」的样子。

### 4.2 六个自动防线

| 机制 | 防什么 |
|---|---|
| **版本锁**（金标 md5 + system.txt sha，评分前强制校验） | prompt 与金标脱节 |
| **口径不变式**（assert 抛 `CaliberError`） | 静默算错（虚高一倍那种） |
| **反向断言**（每条门槛断言都配反向测试） | 断言恒真 |
| **可达性断言**（枚举集合 ⊆ 实际可达分支） | 分支永不进入 |
| **可核率硬闸门**（>0 即中止，禁止跑分） | 编造引用 / 版本脱节 |
| **只读清单**（执行体允许读哪 4 个文件） | 规则文件里混入金标答案 |

### 4.3 三个流程漏洞（都是 C 组主会话自己的错）

1. **渲染早于改 trace** → prompt 过期 → 9 条引用不可核 → 装版本锁
2. **归档早于 agent 写完** → 读到旧产物当新的 → 装独立轮次目录 + mtime 校验
3. **执行体被允许读「裁决记录」** → 裁决记录里有金标答案 → 清理 spec + 建只读清单 + 分离「规则」与「裁决」

**第 3 条的性质最值得记**：它与 A 组在 prompt 里埋「香港反例」**是同一类污染** ——
**在被评对象能看到的材料里植入答案**。区别只在于 A 组污染的是被测系统的输入，
这一次污染的是**评测执行体**的输入。**两者都会让结论失真，且都不报错。**

## 五、这条尺子该怎么用（给使用方）

1. **同口径比较**：所有抽取器必须用**同一匹配阈值**（当前钉在 0.25）、
   **同一评分器**、**同一池口径**。跨组比较前先核对这三项。
2. **两个数一起看**：`PSC-Eval 的 F1` + `PRP 复算结论`（trace 有没有偷偷越出候选集的前提）。
   **两列不一致 = 有问题，且问题在哪立刻可见。**
3. **不要把 F1 当「发现能力」** —— 见第三节。
4. **先看过度声称四类读数**（零方向 precision / 漏判池 spurious / `unknown_source_in_main` / `constraint_violation` 数），
   再看 F1。**一个只会说「这里有域外方向」的抽取器能拿高 recall，precision 是它唯一的刹车。**
