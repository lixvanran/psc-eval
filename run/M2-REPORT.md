## 二、★ 根因：不是"抽不出域外方向"，是 **X 段判定过宽，把好答案当违规扔了**

**⑲-c 预留的敏感性对照在这一轮兑现**：

```
f1_excluding_constraint_violations = 0.6154   ← 现在这个（22 条 CV 被排除）
f1_including_constraint_violations = 0.7568   ← 若不排除
delta = -0.1414
constraint_violation_count = 22
```

**金标里真正的禁区违反只有 1 条（G21）。抽取器判了 22 条 → 21 条是真方向被误判成"禁区违反"而排除出主表。**
排除它们 → recall 被吃掉 → F1 掉到 0.6154。

**0.7568 不能当成绩用**：
- 它是"假设不排除"的假设值；
- 且金标那 1 条真 CV 会被错误地包含进去。

**⟹ 正确处置是修 X 段判定后重跑，不是引用 0.7568。**

**这正是 ㉖-c 那条硬规则的意义**：
> **凡存在「按类别分流」的逻辑，必须有两条断言**：① 可达性断言 ② 降级显式化。
> **X 段判定过宽 = 一条"排除"路径把真方向排掉了。**

## 三、status 那一维：两个口径差 0.21，**待查**

| 跑法 | status 准确率 | introduced_in_synthesis |
|---|---|---|
| 带 `--sweep` | 0.7241（29 对） | 28 |
| 不带 `--sweep` | **0.931**（29 对） | **7** |

**主表 F1 两次都是 0.6154（一致）**，但 **status 配对**与 **`introduced_in_synthesis` 判定**随匹配阈值变化。

**根因（已定位）**：`introduced_in_synthesis` 的信号 (a)「方向文本在中间段找不到」
**实际是用匹配函数实现的**（不是字面包含）→ 阈值不同 → "中间段已生成过"的判定不同
→ introduced 数量从 7 变到 28。

**⟹ 这正是必须修的那一条**：信号 (a) 必须**钉在门槛点同一个阈值上**，
否则这个指标随评测器的扫描参数漂移，**它测的就不是"是否综合阶段新产生"，而是"措辞差多少"**。

**主表 F1 不受影响**（它用固定匹配 + 只看方向是否匹配）→ 0.6154 在两种跑法下一致 ✅

**另**：金标 9 条 `expression_failure` 与 ⑬-b 冲突（㉕-a），已受命改标。
改标**不影响主表 F1**（status 不进 tp/fp/fn），但会改变 status 那一维。

## 五、这把尺子是怎么被造出来的：四次「假通过」

| 次数 | 症状 | 失败方向 |
|---|---|---|
| ⑯-b | `fp` 逐条覆盖 | 报得比实际好 |

| ㉖-a | 循环论证的断言 | 断言的参照物 = 被断言的对象 |

> **不报错 ≠ 算对了。**
> 本项目至今所有最贵的错误，都长成「结果看起来完全正常」的样子。
> **因此每一个数字都必须能回答：「如果它错了，警报在哪？」**
