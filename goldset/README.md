## 0. 先读这一屏：判定规则 v1.1（唯一口径）

**status 描述的是「这个方向对最终决策的贡献」，不是「它在哪一段被提到」。**
判据锚点 = **最终答案段**；判定顺序 = 先看最终答案，再回看中间段。

| status | v1.1 定义 |
|---|---|
| `discovery_failure` | 整个 trace 全文无该方向的任何表达 |
| `realized` | **最终答案中**，该方向作为可操作选项 / 推荐 / 结论出现 |
| `selection_failure` | **最终答案中**，该方向被明确排除、否决或推迟（含「不建议 / 不推进 / 暂不采纳」） |
| `expression_failure` | 中间段明确保留了该方向，但**最终答案完全未提及** |

```
最终答案里提到它了吗？
├─ 提到了 ──→ 作为可操作选项/推荐/结论出现？ → realized
│            └─ 明确排除 / 否决 / 推迟？        → selection_failure
└─ 没提到 ──→ 中间段明确保留过吗？
               ├─ 保留过 ──→ expression_failure
               └─ 没保留 ──→ discovery_failure
```

### 为什么「推迟」算 selection_failure 而不是 expression_failure

推迟与否决在**决策后果上等价**——都没产生可操作增量。更重要的是：
**expression_failure 的诊断价值要求它只覆盖「无声消失」**。如果「明确推迟」也归它，
这一类就退化成「所有没落地的」，失去区分能力——而那恰恰是这把尺子要诊断的核心：
是「活过了筛选却在合成时丢了」，还是「压根没往下走」。

### decision_effect 的通用原则（⑯ §⑤）

> **`decision_effect` 量的是「若该方向进入最终答案会不会改决策」，
> 它与该方向现在有没有被采纳、是不是被推迟完全无关。**
> 所以判 effect 时**不要看它在最终答案里是被采纳还是被搁置**，只看「若采纳，主推方案会不会换」。
> ⑬-a 的两分法：**替换主推方案 / 否定前提** → `conclusion_flip`；**并列多出一项可操作元素** → `option_added`。

### ⑭-b 结构性判据（v1.1 的细化：不看措辞，看结构）

> **看最终答案里该方向有没有产生「当下能执行的动作」。**
>
> | 最终答案里该方向… | 判定 |
> |---|---|
> | 给出**当下可执行**的动作（试点 / 本月启动 / 去谈 / 调参数 / 落成规则 / 当期立项） | `realized` |
> | 只列为**议题 / 未来事项 / 排期到下一轮 / 转交他人 / 下轮再议**，**无当下动作** | `selection_failure` |

配套的 tie-break（判据打架时用）：

1. **「转交他人决策」= 推迟**（G12⑤⑥ 上报给法务 + 明确不落地 → SF），**不等于**「对外沟通 / 去谈」——
   区别在于**该方向本身有没有被安排动作（谁 / 何时 / 做什么）**：G09⑤「与市里沟通口径」是对该方向的推进 → `realized`。
2. **「当期立项评估」= 当下动作**（G05③ 单独立项评估 → `realized`）；**「排期到未来 / 条件触发后再议」= 推迟**（G11① 列入 2027 年规划议题 + 条件触发 → `selection_failure`，**已按裁定改标**）。

   **★ 判据锚点对（并排看就懂了「有当下动作 vs 无当下动作」）**：

   | | 最终答案原话 | 判据 | status |
   |---|---|---|---|
   | **G05③** | 「③ 边缘推理**值得单独立项评估**」 | **当期立项** = 当下动作 | `realized` |
   | **G11①** | 「⑥ 建议**作为 2027 年规划的独立议题**，正式评估…**如果**落地后仍频繁出现抢占冲突…**那时再上**」 | **排期到未来 + 条件触发** = 无当下动作 | `selection_failure` |

   G11① 也是 25 条选择失败里**唯一没有显式否决词**的一条（其余 24 条都含否决/推迟类措辞）——
   **否定词启发式会漏掉它，结构性判据能抓住它**（这正是 ⑭-b 换判据的实际收益）。
   verify.py 因此新增 `DEFER_STANCE`（纯推迟词表）：选择失败 = 含否决词 **或** 含推迟词。
3. **status 与 effect 分离**：action 是否"影响本期主结论"由 `decision_effect` 承载，**不作为 status 的判据**（G03①「不要作为本项目的前置条件」不改变它有当下动作这一事实）。

### 三条派生约定（都已写进数据，不是隐含）

1. **最终答案中的否定性陈述不构成「体现」。** G14 刻意设置了「最终答案用肯定语气复述了一个已被否决的方向」，其 stance 仍是否定 → `selection_failure`。
2. **「转交他人决策 / 列为目标状态 / 下轮再做」= 推迟。** G12⑤⑥（上报给法务决策）、G13②（作为目标状态去谈）、G23⑦（本轮不引入治理委员会）都因此从 `realized` 改判为 `selection_failure`；而 G10⑤⑥（本月就启动、有责任口）保持 `realized`。**区别是最终答案对方向本身有没有推进动作**，不是"有没有提到它"。
3. **事实复述 ≠ 方向被提出。** G21 的 trace 复述了"只有 1 人值班"，但从未把"外包夜间值守 / 改排班"作为候选方向提出 → `discovery_failure`（`expected_source: task`）。

### 状态词表（组内约定）

- 金标文件写 `discovery_failure`；抽取器输出写 `not_generated`（canonical）；**评测器双向归一**，报告统一用 `not_generated`。
- `decision_effect` 五值制取代旧的 `would_change_decision` 布尔位，**旧字段已从金标中删除**（两者语义重叠，并存会在不一致时静默走错分支）。章程 §坑 3 的硬闸门改由 `decision_effect ∈ {conclusion_flip, option_added}` 承载（59 条里 50 条满足）。

### 字段说明

| 字段 | 含义 |
|---|---|
| `initial_frame` | 四段式：`【候选集】` / `【封闭性】` / `【评估维度】` / `【硬约束】`，末行 `域外参考（被排除在解空间之外，不作为候选）` |
| `trace` | 字符串数组。**最后一段是完整最终答案**（以「最终答案：」开头），前面是阶段 1-N 的摘要 |
| `gold.out_of_frame_directions[].direction` | 该域外方向的一句话描述 |
| `.status` | 四类之一（v1.1 定义，见上） |
| `.evidence_quote` | **最终答案里（或中间段里）的一段连续逐字原文**，不带外层引号。`discovery_failure` 必须为空串 |
| `.evidence` | 非发现失败 = 与 `evidence_quote` 相同；发现失败 = 判定依据全文（"trace 中无对应内容，预期方向应来自 X"） |
| `.notes` | 判定说明：定位到 trace 哪一步、最终答案对它是什么 stance、容易看走眼的地方在哪 |
| `.decision_effect` | `conclusion_flip` / `option_added` / `ranking_only` / `additive_only` / `none`。**量的是「若该方向进入最终答案会不会改决策」，与它现在有没有被采纳无关**（本次改标前后该分布未变） |
| `.expected_source` | 仅发现失败填：`task` / `external` / `gold_author`（该方向"本该被想到"的来源） |
| `gold.frame_note` | **金标专有字段**：该题的「域外参考」（被排除在解空间之外的方向清单）。**抽取器不可见**，仅评测器可见，**不进可核语料**。裁决 ⑨：它原先在 `initial_frame` 里，等于把答案印在题面上（开卷泄漏） |
| `_domain` | 领域标签（辅助字段，30 个互不重复） |

### 抽取器输入契约（闭卷）

抽取器只看得到三个字段：**`task` + `initial_frame` + `trace`**（都在顶层；`gold` 整块不进抽取器输入）。
`initial_frame` 严格是四段式（`【候选集】`/`【封闭性】`/`【评估维度】`/`【硬约束】`），**不含「域外参考」**——
域外参考在 **`gold.frame_note`** 里，评测器可见、抽取器不可见，且**不得进可核语料**。

闭卷下的域外判定规则（这就是三段式模板的意义）：
> **方向不在【候选集】里 → 域外。** 只需要知道域内是什么，不需要知道域外是什么。

## 2. 任务来源

30 道题**全部为人工构造**，非改编自任何现有题库或论文。构造流程：

1. 先定一个**真实的、两边都有代价的两难**（有硬约束、有利益冲突、有明确的失败模式），再倒推 trace；
2. 每题写一条 `initial_frame`，并**显式把"域外"写成排除项**——这决定了什么算逃逸；
3. 在 trace 的阶段 3 生成 5–8 个候选方向，**其中 1–3 个落在域外**；
4. 按四类失败分别设计"它在最终答案里是什么 stance"：采纳 / 排除或推迟 / 中间段保留但最终答案不提 / 全程不出现；
5. 逐条写 `evidence_quote`（必须是 trace 的连续逐字子串）与 `notes`（含容易看走眼的地方）。

可复现：`python3 source/build.py` 会重新生成 `gold_v1.jsonl`（含全部硬校验：逐字子串、**status 与最终答案 stance 自洽**、发现失败必须留空、显式否决/采纳措辞校验、域外哨兵词校验）。

## 3. 证据逐字自查结果

`verify.py` 的三档判定：**exact** = 原样命中；**punct** = 仅引号/空白差异；**ungrounded** = 找不到。

```
③ evidence 三档 : {'exact': 54, 'discovery(免检)': 5}
   可核率 = 100.0%   ungrounded 占比 = 0.0%（硬门槛 < 5%）
```

- 54 条非发现失败方向：**54 条全部 exact**，ungrounded = 0。
- 5 条发现失败方向按裁决 ②-b 免检（`evidence_quote` 留空，依据写在 `evidence` / `notes`）。
- 早期版本曾有 32/153 处不可核（跨段拼接 + 改写措辞 + 4 处把批注误放进引号），已全部改为**一段连续逐字原文**；跨段信息一律移进 `notes`。
- v1.1 改标后，**realized / selection_failure 的引用一律改指最终答案段**（原来一半指取舍段），可核率仍是 100%。

**⑮-b 去模板化**：9 条表达失败方向的取舍段措辞已全部改写为**各不相同的保留方式**（暂时搁着 / 先不落笔 / 记一笔 / 提了但没进方案 / 挂在待评估清单里 / 算长期选项 / 先当研究议题 / 备选项 / 先备着），
`verify.py` 带**可执行检测**：这 9 条的 `evidence_quote` 不得有 3 条以上共享同一开头模式。
原先 9 条全是「保留为 + 某种未来事项」——盲评 A/B/金标三方的 9/9/9 高一致是**措辞模板化造成的假可靠**，不是"这一类天然容易判"。

**可核语料口径**（裁决 ②-a / ⑧-e）：
- 逐字校验语料 = **完整 trace（含最终答案段）**；
- 但「该方向是否出现在最终答案里」这项判定**不能用裸 substring**，要用方向级匹配（方向描述与最终答案措辞通常不同）。本集的做法是：**最终答案里每个域外方向都用它的阶段 3 编号（①②③…）点名**，并让 `evidence_quote` 指向那一句表态——这样方向级匹配退化为"编号 + stance 词"两步，且可机械核对。
- task **不进入**可核语料；它只出现在发现失败条目的 `evidence` / `notes` 与 `expected_source` 标记中，不计入可核率分母。

## 7. 开卷 vs 闭卷：词法捷径与真实增量（尺子的自曝机制）

### 7.1 修正后的命题（重要）

上一版我写过"词法捷径在 status 上白拿分与锚点位置无关"。这个观察成立，但**归因要换**：

> **「域外判定一旦在 `initial_frame` 里被明示，尺子就退化成字串匹配。」**
> 真正的失效点不在 status 的锚点位置，而在**题面是否泄漏了答案**。

原先的 `initial_frame` 里带一段「域外参考（被排除在解空间之外，不作为候选）：……」，逐条列出了 3–5 个**具体方向**，
其中大部分正是金标里的域外方向——而词法基线判域外的方式，恰恰是拿字符二元组与这段文字求重叠。
**那是开卷考试。** 裁决 ⑨：这段已从 `initial_frame` 移除，改存金标专有字段 `frame_note`。

### 7.2 两个口径的实测（8 变体 × 阈值网格 = 428 点/口径，完整表见 `baseline_scan.csv`）

**两个口径必须分清**（Coder 指出我原来的口径不一致，已修）：

| 口径 | 分母 | 用途 |
|---|---|---|
| **主表口径** | 非 `not_generated` 的金标方向（**54 条**，与抽取器主表同口径，裁决 ②-b） | **门槛基准用这个** |
| 含漏判口径 | 全部金标方向（**59 条**，含 5 条 not_generated） | 历史口径，仅供对照，**与主表不可比** |

| 口径 × 变体 | 域外判定的信息来源 | 最高 F1 | status_acc | 用途 |
|---|---|---|---|---|
| **闭卷 · 主表口径** | 只用 `【候选集】`：方向不在候选集内 = 域外 | **0.5106** | 0.475–0.49 | **主指标 / 门槛基准** |
| 闭卷 · 含漏判口径 | 同上 | 0.4966 | — | 仅对照 |
| 开卷 · 主表口径 | 用「域外参考」做字串比对（答案就在题面上） | 0.7664 | 0.53–0.61 | 对照 |
| 开卷 · 含漏判口径 | 同上 | 0.7387 | — | 对照 |

**开卷比闭卷高 0.2558（主表口径）—— 这 0.2558 就是泄漏答案的价钱。** 闭卷是主指标，开卷只作对照、**不进门槛**。

闭卷基线的失败模式（这才是这把尺子该测的）：
- 域外判定靠"候选文本 vs 【候选集】"的字串重叠，但**【候选集】是抽象术语、trace 里的候选是具体动作**——
  例如 G01 的候选「② 华东前置备货仓（就近发货）」与候选集「仓网选址与形态」的二元组重叠 = 0.000。
  **闭卷的难度本质是词汇错配，不是语义难懂**：人是能判的，词法判不了。
- 域外方向与【候选集】的词汇重叠：min 0.000 / **中位 0.056** / max 0.278 —— 分布贴地，说明闭卷可分性良好（不是靠运气）。
- `discovery_failure` 全部漏报（trace 里没有的东西，词法原理上无从判断）。

### 7.3 门槛

裁决 ⑨-c：门槛基准 = **所有基线变体 × 所有阈值点的最高 F1**（阈值可调 → 门槛可被放水，必须取高）。

```
闭卷基线最高 F1 = 0.5792【主表口径，池已清空】（V1 / oof=0.18 / match=0.25）
开卷基线最高 F1 = 0.7664【主表口径】（V5，泄漏答案）——仅对照，不进门槛
M2 门槛：真实增量 = 抽取器主表 F1 − 0.5792 ≥ 0.10  ⟹  抽取器主表 F1 ≥ 0.6792
泄漏的价钱（主表口径）= 0.7664 − 0.5792 = 0.1872
```

### 7.3 门槛口径（⑪-a 最终裁定）

**★ 计分池口径：零方向条目必须整条清空**（裁决 ⑧-c）。
评测器在**池层面**清空 G26–G30（`pred_main, pred_miss = [], []`）；基线若不清空，
这 5 条上的 **15 个预测会被算成主表 FP**（`fp=51` 里就有 15 个来自它们）⇒ **基线被低估 0.06**。
本集的 `score()` 已与评测器对齐（池层面清空），两条独立路径（我的 8 变体扫描 / 评测器 scorer+matcher）

### 7.4 基线自身的口径自检（防止"静默算错"）

`score()` 内置三条 assert，每次扫描都跑：
```
主表分母：tp + fn == 非 not_generated 的金标方向数（54）
FP 口径 ：fp + 已匹配数 == 预测总数
含漏判分母：tp_f + fn_f == 全部金标方向数（59）
```
起因：Coder 指出我的口径与抽取器主表不一致，追查时发现我自己的 `score()` 里
**`fp` / `tp_f` / `fn_f` / `fp_f` 是逐条覆盖而非累加**（`fp` 取的是最后一条的 FP），
导致当时的 F1 虚高到 0.938。这类 bug 的特征是**"报出来的数比该数大"、且没有报错**——
所以口径自检必须固化在代码里，而不是靠人看数。

### 7.5 措辞规范的适用边界（必读）

- v1.1 的判据锚在**最终答案段**（语义判据），但为了让 stance 可机械核对，本集让每个方向在最终答案里
  **以阶段 3 编号点名 + 显式表态词**呈现。这是**呈现规范**，不是判定规则。
- 呈现规范**仅适用于本金标集**。接真实系统 trace 时，status 判定必须回到语义判定，**不得依赖任何特定措辞**。
- 本集是**合成语料**，迁移性未验证（C 组章程 §6 同此口径）。基线分数会随呈现规范变化而变化，所以它必须每次一起报。

## 8. 封闭性：为什么 30 条全是 `open`

`【封闭性】` 全部填 `open`，理由是这批题的**常规候选解在任何一条里都不穷尽**——包括看起来最"封闭"的 G24（合同条款谈判）：拆完期限、权利分项、付款、媒介清单之后，仍然存在双窗口发行、三方分账这类**结构性替代**，而那正是 G24 的两条发现失败。
把封闭性显式写出来，是为了让"逃逸测试"里的"新候选"一类**可判**：当框架声明 `open` 时，任何 trace 之外的新方向都属于合法逃逸，不应被记为抽取器失败。

4 条 not_generated 全部落进"抽取器没有义务发现"的桶：2 条 `gold_author`（标注者主观产物）+ 2 条 `low_reportability`（⑰-b 第 7 类逃逸，候选集里有相近措辞 → 闭卷抽取器读到会判成域内 → 天然假阴性）；
第 5 条（G21 外包夜间值守）触碰硬约束禁区 → 进 `constraint_violation_candidates`。
**换句话说：本集里没有任何一条"抽取器应当能报出"的漏判**，因此"漏判召回"这一维在闭卷金标上**测不到**——
不是抽取器不行，是**靶子不可达**。要测这一维，需要另配可报出的漏判方向（或用 ⑰-b 的前提识别能力单独做探针）。

**闭卷下 `not_generated` 召回结构性偏低**（裁决 ⑮-e，不开口子）：
在 `open` 框架下，「本该被想到」的方向往往只是"题面给了但 trace 没用的信息"，
而那些通常落在【候选集】覆盖的机制内 → 判为域内 → 不可报；
**闭卷抽取器最后只能"自己构造一条 not_generated"，很可能与金标枚举的那条不同。**
所以闭卷下的 `miss_detection_recall` 低**不是抽取器缺陷**，更可能是"闭卷无法复现金标的枚举选择"。
本集 4 条 not_generated 的 `expected_source`：task 2 / gold_author 2（主召回分母 = task 的 2 条）。

**status 准确率不是这把尺子的主要区分度来源**（裁决 ⑪-c，正式裁定）：
闭卷基线 status_acc 仅 **0.475–0.49**（开卷 0.53–0.61）——stance 词在最终答案里是**明写**的，
status 这一步闭卷下也能被词法蒙对一大半。**status 准确率仍报告**（它是抽取器质量的一部分），
**但不得当作尺子的判别力证据**；报告必须写明这一点，否则读者会把「status_acc 0.48」误读成「尺子很严」，
实际是「**status 这一步词白送**」——**这两个数在报告里长得一模一样**。

**闭卷下 `zero_direction_precision` 会降 —— 这是真实难度，不是 bug**（裁决 ⑨-f）：
闭卷下要判「没有域外方向」，必须确认 trace 里出现的**每一个**方向都在【候选集】内，这显著难于开卷。
若降幅超出预期，说明的是**闭卷金标的可判定性有问题**（候选集描述不够具体），要回改金标，不是放宽门槛。
两种情况要分清——本集已用「域外方向 vs 候选集 词汇重叠」分布（中位 0.056 / max 0.278）证明可分性良好。

## 13. 已知盲区与补救路线（⑵-b / ⑵-c；本节为文档，金标未动）

### 13.1 普适结论：`not_generated` 在严格 in_frame 下几乎不可构造

本集用三条独立途径各堵一次（⑵-b）：

| 途径 | 表现 | 本集落点 |
|---|---|---|
| ① 违反禁区 | **不该报**（题面说"不能动"的东西） | G21 外包夜间值守 → `constraint_violation_candidates` |
| ② 标注者主观产物 | **不公平**（只有作者知道该想到什么） | G24① 权属重新认定、G25① 三方分账 → `author_only` |
| ③ 被候选集措辞遮蔽 | **结构上不可报**（闭卷读到会判成域内） | G24② 双窗口、G25② 取消本地居民优先 → `low_reportability` |

> **在「域外方向」框架下，`not_generated` 这一类在闭卷 + 严格 in_frame 定义下几乎不可构造。**
> 除非专门设计「题面给了线索、但方向确实域外」的任务，否则**漏判召回测不出来**。
> 这不是本项目的个案，是「问题空间构建」这类评测的**通用陷阱**——它直接影响 D 组的设计：
> D 组要学的是"何时该想到域外方向"，**而这个能力恰恰是本尺子测不到的**。

### 13.2 PRP（前提识别能力，㉑-c）：一个更强的替代测法

> 对每道题：①从【候选集】识别它**依赖的隐含前提 P**；②检查 trace **有没有按 P 走**；
> ③若没有 → **「推翻 P」本身就是该题的一条域外方向**。

**它比"从正例里挖漏判"强在两点**：
- 线索来自 **trace 与框架的落差**，抽取器能自己发现，**不需要金标事先枚举**；
- 它**天然满足 §13.1 的三面围堵**：可从题面推出 ✅ / 它就是候选集措辞的反面（不被遮蔽）✅ / 推翻前提不等于触碰禁区 ✅。

**但 PRP 要成立，必须补一个检查**（这是本 agent 的贡献，见 13.3）：**trace 有没有已经提出过"推翻 P"**。
若 trace 已经提了，那这条方向**已经在金标里**（realized / expression_failure），PRP 就不再产出 `not_generated`。
→ 所以 PRP 的 `not_generated` 产出条件是 **「trace 违反了 P，但从未提出推翻 P」**，这是一个更精确、也更稀有的事件。

### 13.3 PRP 的三探针分解（建议写进 ㉑-c 任务书）

把"前提识别"从**被计分的路径**挪到**被给定的路径**，PRP 才既可测又可闭环：

| 探针 | prompt 给什么 | 问什么 | 测的是 | 计分 |
|---|---|---|---|---|
| **A 前提识别** | 只有题面 + 框架 | "候选集依赖的隐含前提是什么？" | 能不能说出 P | 对金标的 P 做等价性判定（人工/模型） |
| **B 违背检出** | **P 已经在 prompt 里** | "trace 有没有按 P 走？" | 能不能发现落差 | 二值/三值（follows / violates / unclear） |
| **C 逃逸方向生成** | P + 落差位置 | "由此产生的域外方向是什么？" | 能不能命名逃逸方向 | 与金标方向做匹配（同点比较） |

**关键收益**：探针 B/C **把 P 给出去**，于是"推翻 P"成为**闭卷可报的合法靶子**——
主召回分母不再为 0（可用 `expected_source = "prp"` 新桶进入主统计），而"前提识别"的能力被单独隔离在探针 A。

### 14.3 残余遮蔽体检（2 条，需逐条判语义）

`verify.py` 的「候选集遮蔽体检」用字符二元组重叠做**词汇指标**扫描（阈值 0.20）。
本轮改完后的残余 2 条：

| 条目 | 重叠 | 为什么判定为「词汇碰撞」而非「语义遮蔽」 |
|---|---|---|
| G15 | 0.375 | 方向依赖的机制是**合并资格的定义**（谁能合并），而候选集讲的是 **review 人数**——机制不同，只是都出现「维护者」「review」 |
| G19 | 0.269 | 方向依赖的机制是**激励挂钩**（评优），候选集里没有激励类杠杆——只是都出现「员工」「AI 工具」 |

因此该检查在 `verify.py` 里作为**警告 + 显式清单**报告，而不是硬报错：
硬报错会逼着把候选集改成不自然的措辞（而自然措辞正是本集要保的东西）。
检查本身保留，作为将来新增方向时的常规体检项。

### 14.4 表达失败类的稀缺性（⑬-b 带来的结构性变化）

⑬-b 是后裁决且语义更正确：在它之下，`expression_failure` 天然稀有——
一个方向要么被**明确推迟**（→ selection_failure），要么进了**最终答案**（→ realized），
只有「trace 保留了、但合成时没写进最终答案」才落入这一类。真实系统里这种情况极少。
本集因此有 6 条**定向构造**样本（`constructed_for: "expression_failure"`）——
**显式标注，不伪装成自然分布**；报告里读到这 6 条时必须知道它们是构造样本。
