## 1. 前提撰写的 5 条硬约束

1. **前提必须是"关于世界的信念"，不是候选集某一项的复述。**
2. **必须指到 trace 的具体段落**（可定位到「阶段N｜xxx」或「最终答案」）。
3. **违反点定位不到 → `trace_follows_premise` 记 `true`**（即"没找到违反"），**不要硬凑**。
4. **若 trace 已提出推翻 P 的方向，抄下那条方向原文**（用于与金标方向对照）。
5. **`premise_kind` 用规定枚举**，归不进去填「其他」。

### 1.1 正反例对照（"关于世界的信念"怎么判）

| | 例句 | 判定 |
|---|---|---|
| ❌ 差 | 「候选集包含『仓网选址与形态』」 | **候选集的复述** —— 违反它 = 换了说法，不是推翻了什么 |
| ❌ 差 | 「候选集包含『导师匹配算法』」 | 同上 |
| ✅ 好 | 「缺货中断造成的客户损失必须由我方自己承担」 | **关于世界的信念** —— 违反它 = 把风险转嫁出去（这才是真正的域外方向） |
| ✅ 好 | 「学生的科研分歧可以通过既有导师与院系渠道解决」 | 同上 |
| ✅ 好 | 「治理权与商业资助无关」 | 同上 |

**判别方法**：把这句话当成前提，问「**如果它不成立，候选集合里的做法还能做吗？**」
- 能做 → 它是背景信息，**不是前提**；
- 做不了 → 它是前提。

### 1.2 前提不得与硬约束禁区重叠（风险控制第 4 条）

禁区是**不可触碰的边界**（题面说"不能动"的东西），前提是**候选集赖以成立的信念**。两者容易混：

| | 例子 | 归类 |
|---|---|---|
| 禁区 | 「维持数据权属归属与现有用工/排班制度不变」 | **禁区** —— 触碰它 = `constraint_violation` |
| 前提 | 「夜间批处理失败属于流程与可靠性问题，解法在技术路径与告警流程里」 | **前提** —— 它没说"不许动权属"，只说了"问题的所在" |

## 3. `trace_follows_premise` 三值分布

| 值 | 含义 | 条数 |
|---|---|---|
| `true` | trace 的**实际行为**仍建立在 P 之上（哪怕它提出过推翻 P 的方向但没采纳） | 11 |
| `false` | trace 的实际行为**违反**了 P（推翻 P 的方向被采纳 / 被写进最终答案） | 14 |
| `partial` | 一部分遵守、一部分违反 | 5 |

`premise_raised_in_trace`：提出过推翻 P 的方向 = 22 条 · 从未提出 = 8 条。

**两种组合各有含义**：
- `true` + `raised=true`（如 G02、G16、G17）：**trace 考虑过推翻前提，但最终没有采纳** —— 这是"前提被识别到却没被处理"的信号。
- `true` + `raised=false`（如 G24、G25、G26–G30）：**trace 完全没意识到前提的存在** —— 前提在框架里是隐含的、没被触发。

## 4. 探针 C 的靶子：**本集为 0**（独立确认）

> **探针 C 的靶子条件 = 「trace 违反 P，但从未提出推翻 P」。**

逐题判定（`build_premises.py` 自动输出）：

```
探针C 靶子（违反前提且从未提出推翻）: 无 ✅
```

**原因**：金标构造方造 trace 时遵循「**违反前提就必须提出**」，
这个构造规则本身消灭了探针 C 的靶子。
⇒ **探针 C 的产出必须靠新造的「前提依赖型任务」**（trace 悄悄违反前提而不提），
这与 ㉑-c 写下的"新增一类任务：前提依赖型任务"一致。

**交叉校验（前提文件 ↔ 金标方向，22 条有对应）**：
每一条"推翻 P"的方向都能在金标里找到对应方向，相似度 0.51–1.00，状态自洽：

| 金标状态 | 条目 |
|---|---|
| `realized`（推翻 P 的方向被采纳） | G01 G03 G04 G05 G07 G08 G09 G10 G20 G21 |
| `selection_failure`（提出了但被否决/推迟） | G02 G11 G12 G13 G14 G15 G17 G19 G22 G23 |
| `expression_failure`（提出了但最终答案没体现） | G16 G18 |
| 不在金标（trace 未提出） | G06 G24 G25 G26 G27 G28 G29 G30 |

**这张表本身就是一次交叉验证**：前提清单是**独立于金标构造过程**写出来的，
它对"哪些方向真的推翻了前提"的判断，与金标里的 status 分布吻合。

## 6. 3–5 个难写的前提（"关于世界的信念"很难从候选集反推）

1. **G04「稿件的效度缺陷总能通过要求作者补材料来纠正」** ——
   这条前提离禁区只有一步之遥（禁区是"在常规同行评审的权限内"= **权限**，
   前提是"补材料总能纠正"= **充分性**）。两者措辞相近、极易混为一谈。
   *难在*：要写出的是"充分性信念"而不是"权限边界"，而且必须能解释为什么 ethics flag 越了它。

2. **G21「夜间批处理失败属于流程与可靠性问题，解法在技术路径与告警流程里」** ——
   本题的禁区（数据权属、用工/排班）几乎覆盖了所有"换条路走"的方向，
   要找到一条**不碰禁区、又能被 trace 违反**的信念，只能从"问题的归属"这个角度下刀。

3. **G22「录用决定必须由我方基于岗位需要作出，不能由不承担用工责任的外部方决定」** ——
   trace 的实际行为（把"不同意背调"改成人工复核、由 HR 委员会决定是否继续）
   已经轻度动摇了这条，但"流程层 vs 决策层"的边界很难在前提层面说清。

4. **G26「课堂冲突可以通过座位安排、记录方式与支持机制来减少，不需要改变班级与评价的组织方式」** ——
   这条把"组织方式"排除在外，但禁区也冻结了评价口径，两者高度重叠；
   写成前提时必须刻意避开"评价"这个词，否则会被误判为禁区。

5. **G13「收购交易谈定的东西在整合期是既定的，整合不必触碰它们」** ——
   候选集里全是"整合动作"，前提却在谈"整合的边界"；
   写出来容易变成禁区的复述，而不是一句关于世界的信念。

## 7. 一句话

**前提清单不是"题目的另一种写法"，而是"这套做法建立在什么信念上"的清单**——
它的价值在于：凡是被它标成 `false` 的题，trace 都真的越过了那条信念；
而**凡是被它标成 `true + raised=false` 的题，正是"前提从未被意识到"的地方**（本集 8 条）。
这两组数，可以直接用来设计 M3 的「前提依赖型任务」。

## 8. 前提线索泄漏审计（`source/leak_audit.py`）—— 为 ㉔-c 的"前提线索显隐度"实验做的工具

> ㉔-c 的杠杆：**改题面（让隐含前提在题面上留下可推的线索）就能把某类能力变成可测的。**
> 但要做这个 A/B 实验，必须先堵掉一个失败模式：
> **如果 trace 自己把前提讲出来了，删掉题面线索不会有任何变化**（低线索版会从 trace 泄漏），
> A/B 会得到一个**无法解释的零差异**——是"线索不重要"还是"实验坏了"？分不清。

`leak_audit.py` 逐题给出两个数：

| 数 | 含义 | 判定 |
|---|---|---|
| `task_clue` | 题面各句与前提的最大二元组重叠 | ≥0.25 = 题面留了线索 |
| `trace_clue` | trace 各句与前提的最大二元组重叠 | <0.15 = trace 没把线索讲出来 |

```
python3 source/leak_audit.py            # 逐题表
python3 source/leak_audit.py --only G25 # 单题（含最像线索的句子原文）
python3 source/leak_audit.py --json     # 机读
```

**本题集的结果**：干净 A/B 候选仅 **G11**（且它的 trace 主动反驳了它的前提，属"前提被触及"而非"前提可疑"）；
"改题面无效（线索也在 trace）"的是 **G04、G13**。
⇒ **现有 30 道里没有一道能直接做这个 A/B** —— 它必须**新造一对题**（与 ㉑-c 的"前提依赖型任务"是同一件事）。

### 8.1 顺带量出来的一个区分（对补救路径有影响）

**G25② 的前提在 trace 的最终答案里是可见的**（最终答案直接讨论了「本地居民优先」这一条件）——
它之所以被判"低可报性"，**是因为【候选集】的措辞把它遮蔽了**（候选集写「在既有『本地居民优先』条件下的分配方式」），
**不是 trace 没讲**。

⟹ **两类"漏判不可测"的补救路径不同**：

| 遮蔽来源 | 例子 | 补救 |
|---|---|---|
| **【候选集】措辞遮蔽** | G25② | **改候选集一句**即可（成本低，30 道都能受益） |
| **trace 从未触及** | G24① 权属、G06、G26–G30 | 只能**新造任务** |

⟹ 也就是说：**"漏判不可测"里有一部分只是"框架写得太含蓄"，那是能修的**——
这与 ㉔-c 的杠杆是同一件事的两种表述（**改题面** vs **改框架措辞**）。
