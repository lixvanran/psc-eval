## 漏洞 ①：`selection_failure` 与 `expression_failure` 的分界

**裁定：三条全采纳。**

### ①-a 改上游 trace 格式（采纳，且优先）

**这是根本解法。** 改判定标准是治标，改采集端才是治本。

**PSC-Eval 的 trace 接口规范（新增，必填）**：

```
trace 每一项必须携带两个可选但强烈建议的字段：
  candidates[]  —— 该阶段进入过候选池的所有方向（显式清单，含被淘汰的）
  dropped[]     —— 被淘汰的方向 + 淘汰理由（谁否决的、为什么）
```

**这立刻可接驳到 A 组**：multi-mind 的 N2 阶段本来就有候选清单，N3 本来就有攻击/盲点结果。**A 组的 trace 结构天然满足这个要求**——它已经具备区分 selection 与 expression 所需的信息，只是没被显式化。这是 C 组对 A 组最便宜的一份礼物。

**只有 N0/N1 阶段的 trace（还没进候选池）不适用**，那里的方向若消失，判定为 `not_generated` 或 `status_ambiguous`。

### ①-b 并列报告（采纳）

验收时同时报告：
- `status_accuracy_strict` —— 全部可判条目的 status 准确率
- `status_undecidable_rate` —— 标记 `status_ambiguous` 的条目占比

**这两个数要一起出现。单看准确率会掩盖尺子的盲区。**

### ①-c 保守默认裁定（新增裁定）

当一条方向**既无否决痕迹、又无保留痕迹**（即被静默丢弃）时：

> **默认判 `selection_failure`。**

**理由**：语义上「被静默丢弃」更接近「被剔除」，而非「被保留但未在最终答案呈现」。后者要求存在"活过筛选"的正向证据；前者没有。两类都缺证据时，缺的是**保留的证据**，所以归到 selection。

**配套新指标** `selection_expression_separability`：
= 在有独立裁定（人工或改进后的 trace）的样本上，抽取器把 selection/expression 判对的比例。
**这个数字本身就是尺子的质量刻度**——它比 status_accuracy 更能说明这把尺子能不能用来区分 A 组最关心的那两类失败。

### ①-d 结论

**这条不改规格的可判性，只改统计方式。** 真正的裁决落在 ①-a：**A 组、B 组提供的 trace 若不带候选清单/淘汰记录，PSC-Eval 对 selection/expression 的判准率就不可信。** 这条要写进 M4 跨组接驳的**前置条件**。

## 漏洞 ②：`not_generated` 的召回天花板

**裁定：两条都采纳。**

### ②-a 金标只收关键漏判（采纳）

金标集中 `not_generated` 的条目，**只收会导致结论错误的关键漏判**（即「如果想到了，决策就会变」的方向）。

次要漏判（想到了也不改决策的）**不收**。理由：收进来会稀释召回、且引入主观噪声。

**这与规则 4 的 `decision_effect` 判据一致**——关键漏判 ⟺ `decision_effect ∈ {conclusion_flip, option_added}`。

### ②-b 不计入主 F1（**裁定：不计入**）

**这是对 Coder 默认值的推翻，明确说明理由：**

1. `not_generated` 的召回是**下界**（只能命中已枚举的漏判），把它折进一个总分里，等于宣称这把尺子有确定的覆盖率——**它没有**。
2. 方向匹配（"是不是同一个方向"）与漏判检测（"是不是该想到的"）是**两种不同难度、不同性质的任务**，混在一个 F1 里没有意义。
3. **方法论同源**：B 组的核验器 v4 把「非主张」单列，不混进主统计。C 组沿用同一处理——这是从隔壁组学到并验证过的做法。

**具体改动**：
- 主 F1 / P / R **只统计** `realized` / `selection_failure` / `expression_failure` 三类
- `not_generated` 单独出 `miss_detection_recall`（对已知关键漏判的命中率）
- 两者在报告里**分表呈现**，主表标题写明「不含 miss detection」

**报告里必须同时打上免责句**：`miss_detection_recall` 是下界，不是覆盖率。

## 漏洞 ③：`would_change_decision` 没有量纲

**裁定：批准加 `decision_effect`，并让它取代 `would_change_decision`。**

### 字段变更

**移除** `would_change_decision: bool`
**新增** `decision_effect: "conclusion_flip" | "option_added" | "ranking_only" | "additive_only" | "none"`

### 计分映射

| decision_effect | 计入「有实质改变」 | 说明 |
|---|---|---|
| `conclusion_flip` | ✅ | 结论/推荐实体改变 |
| `option_added` | ✅ | 新增可操作选项 |
| `ranking_only` | ❌（但记录） | 只有排序变 |
| `additive_only` | ❌（但记录） | 只加限定条件 |
| `none` | ❌ | 纯修辞 |

### 为什么用单一字段取代两个字段

`would_change_decision` + `decision_effect` 并存会**自相矛盾**（bool=true 但 effect=ranking_only 怎么办）。单一字段消歧。

### 为什么不要求「实体候选集变化」才算（驳回 Coder 的 ①-a 强形式化）

**在 A 组的场景里，排序变化本身就是决策变化**（志愿填报、方案推荐，排序即决策）。强形式化会系统性误杀 `ranking_only`，把尺子偏向"提出全新候选"这一种能力。

**处理：`ranking_only` / `additive_only` 单独统计为 `weak_effect_count`，不计入主分但完整报告。** 保留信息，不做判定——等 M2 有真数据后再看这两类在真实系统里的分布，那时再决定要不要收紧。

### 对 schema 变更的影响

抽取器输出与金标 schema **同时**改。兼容策略：评测器**同时接受**旧字段 `would_change_decision`（映射为 `conclusion_flip`/`none`）与新字段，v1 报告里标注 `schema_version: 2`，但**金标集必须用新字段**。

## 漏洞 ④：`in_frame` 依赖框架的写法

**裁定：强制统一模板。**（Coder 建议的 ①-a，采纳）

### initial_frame 强制模板（三段式 + 封闭性声明）

```
【候选集】<显式枚举的候选项；至少列出题面蕴含的全部常规选项>
【封闭性】closed | open
          closed = 该候选集穷尽了本题的全部可能解
          open   = 该候选集只是常规解，题面允许更多
【评估维度】<显式列举用于比较候选项的维度>
【硬约束】<不可违反的边界；没有就写"无">
```

### `closed` / `open` 声明是本次裁定新增的关键项

**没有这一项，「逃逸测试」的五类逃逸中，「新候选」一类在描述式框架下无从判定**——这正是 Coder 报告的漏洞 ④ 的根因。强制声明后：

- `closed` 框架下：引入清单外的候选 = 逃逸成功 = 域外
- `open` 框架下：「新候选」一类逃逸**自动失效**，只剩「新维度 / 新约束 / 新问题 / 重定义」四类可判

### 跨组接驳的前置条件

**任何组要用 PSC-Eval 的数字与别的组比较，必须用同一模板写 initial_frame。**
不满足的，只能做「同一任务内的相对比较」，报告中必须显式标注 `frame_schema: non_conforming`，**不得与 conforming 数据并列排名**。

这条是 C 组建议 M4 接驳时**第一个**要推的东西。

## 补充裁决 ⑤：诱导框架（F1）的构造规范（C 组主会话新增）

Coder 在 README §6 写了 CFC 的接驳点，但**没有定义 F1 怎么构造**。没有规范，CFC 的四格就不可比。

### F0（默认框架）

由任务给定者按 ④ 的模板写，候选集填**题面蕴含的常规解**，封闭性填 `open`（因为常规解通常不是穷尽的）。

### F1（诱导框架）

**在 F0 的基础上，只做一处改动：显式点名一个域外方向。**

```
【新增】请额外评估以下方向：<方向 D>
```

**其余三个段（候选集、评估维度、硬约束）与 F0 完全一致**，只允许在候选集末尾追加 D，且：
- **不得**解释为什么要考虑 D（否则就成了"引导语"而不是"框架"）
- **不得**改动其他任何措辞
- 封闭性保持 F0 的取值不变

### F1 判定

**F1 的最终答案里出现了 D → F1 命中；没出现 → F1 未命中。**

判定是**二值**的，不依赖抽取器的语义匹配（避免 ⑥ 的阈值问题污染 CFC）。

### 「D 选哪来」

D 必须**来自 F0 之外的已知域外方向**——具体来源：
- 金标集里的 `out_of_frame_directions`（C 组自有语料）
- 或 A/B 组提供的问题空间中已知的遗漏方向

**不允许由抽取器现编 D**——那会变成"抽取器自己出的题自己考"。

## 补充裁决 ⑥：阈值校准与人工复核（C 组主会话补充）

### ⑥-a Jaccard 阈值必须扫描

M2 验收时对 0.20–0.60 逐点扫描，画出 F1 vs 阈值曲线，**报告里必须附这张曲线**。0.34 只是默认值，**不得在扫描前用于任何跨组结论**。

**同时报告一个「阈值敏感区间」**：F1 在该区间内变动 < 2% 的范围。跨组比较时，三组的抽取器必须落在**同一区间**内，否则匹配阈值本身就会制造差异。

### ⑥-b 人工复核抽样（强制）

`extractor_spec.md` §8 第 5 条说 `would_change_decision=true` 的条目「建议 100% 人工过一遍」——**「建议」改成「强制」**。

理由：这是硬闸门。硬闸门抽错就等于放水，规格里给的是"建议"，执行时会被省掉。

**v1 阶段（金标集 30 条）的最低复核量**：
- `would_change_decision` / `decision_effect` 为真的条目：**100% 复核**
- `status` 判定：**30% 随机抽样复核**
- 复核由 C 组主会话执行，结果写入 `goldset/README.md` 的复核记录

**复核发现的错误必须回改金标**，并在报告里记录改了多少条——**金标改了却不记录，等于偷偷改了考卷**。

Coder 在报告里写「这是绕过，不是解决」（关于漏洞 ①）。**这个判断是对的，本裁定照此办理**：①-c 的保守裁定只保证统计可用，**真正的解决在 ①-a 的上游 trace 规范**。

## 补充裁决 ⑦（2026-10-18 第二轮 · 源自金标构造方反馈）

### ⑦-a ★ 词法捷径基线 —— 尺子必须自曝偷懒空间

**背景**：金标构造方在统一 trace 措辞时发现，可以把 status 判据**直接写进 trace 的措辞里**
（realized 的取舍段一律写「保留」，selection_failure 一律带显式否决词）。
这样一来，抽取器只需做**关键词匹配**就能判对 status——**尺子退化成词法匹配器**。

这与 A 组踩过的坑同类：**答案的判定依据被写进了被评对象本身**。

**裁定**：

1. 该措辞规范**在合成语料阶段允许执行**。金标需要可控，这是合成语料与真实 trace 的本质差别。
2. **但评测器必须同时实现一个「词法捷径匹配器」，并报告它的得分。**

> **`lexical_baseline`**：一个只做关键词匹配的基线。
> 否决词表：否决 / 不采纳 / 不执行 / 不列入 / 排除 / 暂不推进
> 保留词表：保留 / 采用 / 纳入 / 建议采用
> 报告必须给出：**真实增量 = 抽取器 F1 − lexical_baseline F1**

**理由**：任何评测集都必须回答「用最简特征能做多少分」。如果 PSC-Eval 只比关键词匹配器高 2%，
它几乎没有增量价值。**这个数字是尺子的自曝机制，不报就等于藏。**

**M2 硬门槛**：`真实增量 ≥ 0.10`。达不到说明抽取器没学到语义，**该改抽取器，不该改门槛**。

### ⑦-b `expected_source` 字段（解决金标 discovery 条目的可核性）

**问题**：discovery / not_generated 的方向在 trace 里**不存在**，它的「依据」只能来自 task 文本或标注者的领域知识。
若把 task 纳入可核语料，抽取器就能**引 task 里的内容伪装成「在 trace 里出现过」**，
把 not_generated 误判成有生成——**这会污染最关键的那一类**（漏判发现失败比误判严重得多）。

**裁定**：

1. **可核语料 = trace 段，且不含 final_answer、不含 task**（维持现状，评测器已正确实现）
2. 金标的 not_generated 条目：**`evidence_quote` 留空**（规格 §3.3 已规定），依据写进 `notes`
3. **新增可选字段 `expected_source` ∈ {`task`, `external`, `gold_author`}** —— 记录「这个方向本该被想到」的来源
4. 抽取器输出的 not_generated 条目：**`evidence_quote` 必须为空**（已有 self-test 覆盖）
5. **否决「把 task 扩进检索池」的做法**——理由见上

### ⑦-c canonical 名定义

- canonical = **`not_generated`**
- `discovery_failure` 是它的**别名**；gold 侧与 pred 侧**双向归一**（评测器已实现，有 self-test 覆盖：
  「gold 用 discovery_failure 也进混淆矩阵」「discovery_failure 别名 status_agreement=True」）
- **金标集可以继续写 `discovery_failure`，无需改动**——规格 §3.2 的命名说明已授权
- 报告里的混淆矩阵、`per_status` 统计**一律用 canonical 名**

### ⑦-d 措辞规范的适用边界

⑦-a 的 trace 措辞规范**仅适用于金标集**。
接真实系统 trace 时，status 判定必须回到**语义判定**（有没有否决痕迹 / 保留痕迹），
**不得依赖任何特定措辞**。此边界须写进 README 首屏与 M4 跨组接驳文档。

## 补充裁决 ⑧（2026-10-18 第三轮 · 源自金标定稿复核）

### ⑧-a ★★ status 判定锚点移到「最终答案段」（覆盖原 §3.2 流水线）

**背景**：金标构造方发现一批条目（如 G11⑦、G15⑤、G17⑤⑥、G23⑦）——取舍段写「保留」，
但**最终答案明确说「不建议 / 本轮不推进」**。这类方向对最终决策的贡献是零，
却按原流水线被标成了 `realized`。

**原定义的缺陷**：原 §3.2 的流水线把「取舍段」当判据锚点，于是
**「被讨论过」被当成了「被采纳」**。status 要描述的是**这个方向对最终决策的贡献**，
不是「它在哪一段被提到」。

**裁定：status 定义 v1.1 —— 判定锚点是最终答案段**

| status | v1.1 定义 |
|---|---|
| `not_generated` | 整个 trace 全文无该方向的任何表达 |
| `realized` | **最终答案中，该方向作为可操作选项 / 推荐 / 结论出现** |
| `selection_failure` | **最终答案中，该方向被明确排除、否决或推迟**（含「不建议 / 不推进 / 暂不采纳」） |
| `expression_failure` | 中间段明确保留了该方向，但**最终答案完全未提及** |

**判定顺序（先看最终答案，再回看中间段）：**

```
最终答案里提到它了吗？
├─ 提到了 ──→ 作为可操作选项/推荐/结论出现？ → realized
│            └─ 明确排除 / 否决 / 推迟？       → selection_failure
└─ 没提到 ──→ 中间段明确保留过吗？
               ├─ 保留过 ──→ expression_failure
               └─ 没保留 ──→ not_generated
```

**四条理由**：

1. status 描述的是**对最终决策的贡献**，不是「在哪一段被提到」。
2. **推迟与否决在决策后果上等价** —— 都没产生可操作增量，故归 `selection_failure`。
3. **`expression_failure` 的诊断价值要求它只覆盖「无声消失」**。若「明确推迟」也归它，
   该类就退化成「所有没落地的」，失去区分能力 —— 而这正是 C 组要诊断的核心。
4. 锚在最终答案段后，词法捷径基线**依然可跑**（在最终答案段找否决 / 推迟词），
   但比锚在取舍段更贴近真实语义。

**连带作废**：金标构造方原定的「取舍段措辞规范」（realized 一律写「保留」、
selection_failure 一律带否决词）**作废**。判据不在取舍段，措辞规范随之作废。

**金标改标要求**：G11⑦、G15⑤、G17⑤⑥、G23⑦ 从 `realized` 改标 `selection_failure`，
且 `evidence_quote` 改为**引最终答案里那句否决 / 推迟的原话**（这样 evidence 仍为 exact）。

### ⑧-b `gold_author` 来源的发现失败：保留，但单列

G24 权属、G25 分账两条 `expected_source = gold_author` 的条目**保留在金标中，不剔除**。
理由：这两条正是「什么算域外」最难的部分（词法吃不掉的那部分），剔除会损失最有价值的样本。

**但**：`expected_source = gold_author` 的条目**不计入 `miss_detection_recall` 的主统计**，
单列为 `miss_detection_recall_author_only`。

**理由**：主指标的分母不能是「标注者的领域知识」。把主观项混进主召回，会让这个数
既不可复现也不可跨组比较。

### ⑧-c 零方向条目（G26–G30）：单列为精度探针

**采纳**金标构造方的建议：5 条零方向条目不计入主 F1。

**理由**：「正确答案是没有域外方向」的条目上 recall 无意义（分母为 0），
且被设计成「必须至少报一个」的抽取器必然在这 5 条上失手——拉低 F1 与语义能力无关。

**但必须单独报告两个数（不能只排除不报告）**：

- `zero_direction_precision` —— 零方向条目上判「无域外方向」的正确率
- `zero_direction_overclaim_rate` —— 零方向条目上误报域外方向的比例

**理由**：规则 2 的非对称义务（漏判发现失败 ≫ 误判）会**主动推着抽取器保守**。
零方向条目上的过度声称率低，**说明抽取器守住了这个非对称义务** ——
这是一个**正向质量信号**，比主 F1 更能反映尺子是否可信。

### ⑧-d ★ 词法捷径基线取「多实现最高值」

**复核发现**：C 组主会话独立实现词法基线，得 **F1 = 0.487**（只用 `evidence_quote` 语料）；
金标构造方报 **0.696**（实现不同）。

**同一个「基线」在不同实现下从 0.49 浮动到 0.70** —— 说明「词法捷径 F1」不是客观量，
门槛直接建立在它上面会不稳。

**裁定**：词法基线**必须跑多个实现变体，门槛以其中最高的 F1 为准**。

**变体矩阵**：

| 维度 | 取值 |
|---|---|
| 语料 | ① 仅 `evidence_quote` ② 整条 trace ③ 仅最终答案段 |
| 词表 | 宽（含「不建议 / 不推进 / 暂不采纳」）窄（仅「否决 / 不采纳 / 不执行 / 不列入 / 排除」） |

**全部变体都要报告**（区间本身是信息），但**门槛基准取最高值**。

**理由**：门槛的作用是「证明尺子学到了语义」。那就必须打败**最努力的词法匹配器**，
而不是最容易被打败的那个。

### ⑧-e 引用语料与 status 判定的口径澄清（跨组同步项）

金标构造方提出：最终答案**必须包含在逐字校验语料里**，否则 `realized` 的
`evidence_quote`（按规格应引最终答案原话）必然 ungrounded。

**裁定**：

1. **逐字校验语料 = 完整 trace（含最终答案段）**。排除最终答案的旧做法**作废**
   —— 理由：它让 `realized` 无法举证。
2. 但**「该方向是否出现在最终答案里」这一项判定，不能用裸 substring**，
   必须用**方向级匹配**（`match_fn`）。否则方向描述与最终答案措辞不同就会误命中，
   `expression_failure` 会被系统性误判成 `realized`（这正是旧做法要防的问题）。
3. **新增防伪检查**：若某方向的 `evidence_quote` 只在最终答案段命中，
   而抽取器判的是 `expression_failure` / `not_generated` → **记为违规**
   （与现有「not_generated 带引用被记违规」同构）。

## 补充裁决 ⑨（2026-10-18 第四轮 · 金标复核发现「开卷」缺陷）

### ⑨-a ★★★ initial_frame 里的「域外参考」段必须移除 —— 金标当前是开卷的

**复核发现**：30/30 条金标的 `initial_frame` 都含一段：

```
域外参考（被排除在解空间之外，不作为候选）：<域外方向逐条列出>
```

而金标构造方的词法基线判域外的方式，正是**用字符二元组与这段「域外参考」求重叠比重**。

**这意味着这批金标是开卷考试**：域外方向被直接印在题面上，
基线只需做字串比对就能判定域外。**基线 F1 0.696 的主要来源不是「status 可词法化」，
而是「域外判定可以对着答案做」。**

**真实世界里 `initial_frame` 是「题目蕴含的常规框架」，不会告诉 Agent 哪些是域外** ——
那恰恰是 Agent 要自己发现的东西。把答案印在题面上，这道题就测不出任何东西。

**裁定**：

1. **移除 `initial_frame` 里的「域外参考」段（30/30 全去）**
2. **域外参考保留到金标的新字段 `frame_note`** —— 信息不丢，但**抽取器不可见**（仅评测器可见）
3. `initial_frame` 严格回到四段式：【候選集】【封閉性】【評估維度】【硬約束】
   —— **注：四段式模板本就没有「域外参考」段，那是标注方自行加的**
4. **闭卷下域外判定依然完全可操作**：逃逸测试的「新候选」一类在 `open` 框架下是
   「方向不在【候選集】裡 → 域外」。**只需要知道域內是什麼，不需要知道域外是什麼。**
   这正是裁决 ④ 强制三段式模板的意义所在。

### ⑨-b M2 必须报告「開卷 / 閉卷」双数，主指標用閉卷

| 口径 | 說明 | 用途 |
|---|---|---|
| 開卷 | initial_frame 含域外參考（改前金標） | 對照組：**抽取器複述能力**的上限 |
| **閉卷** | initial_frame 不含域外參考（改後金標） | **主指標**：抽取器真實的域外辨識能力 |

**閉卷數是 M2 的主指標。開卷數只作對照，不進門檻。**

### ⑨-c 門檻基準 = max(所有基線變體 × 所有閾值)

金標構造方實測：其端到端基線的域外判定閾值可從默認 0.10 調到 0.15，
**F1 從 0.696 升到 0.737**。也就是說**門檻可被調參放水**。

**裁定**：
- 門檻基準 = **所有基線變體 × 所有閾值點的最高 F1**
- 基線閾值掃描點至少覆蓋：域外判定閾值 {0.06, 0.08, 0.10, 0.12, 0.15, 0.18, 0.22, 0.26}、
  stance 閾值、方向匹配閾值（與 Jaccard 掃描合併）
- **報告必須附完整掃描曲線** —— 調參空間本身就是信息

### ⑨-d 對「尺子退化成詞法匹配器」原命題的修正

C 組主會話原命題（裁決 ⑦-a 引入）：
> 「如果 status 判據被寫進 trace 的措辭裡，抽取器只需做關鍵詞匹配就能判對 status，尺子就退化成詞法匹配器。」

**金標構造方提出反例**：v1.1 把 status 錨點從取捨段移到最終答案段後，基線 F1 仍為 0.696，
**說明詞法捷徑在 status 上白拿分與錨點位置無關**。

**裁定：原命題過強，接受反例的部分。** 修正為：

> **「域外判定一旦在 `initial_frame` 裡被明示，尺子就退化成字串匹配。」**

即：**真正的失效點不在 status 的錨點位置，而在題面是否洩漏了答案。**
這是金標設計問題，不是尺子設計問題 —— 修正手段就是 ⑨-a 的閉卷改造。

### ⑨-e 候選集粒度檢查（已查，結果健康）

| 指標 | 實測 |
|---|---|
| 【候選集】項數 | min 6 / max 18 / **中位 9** |
| 域外方向數 / 候選集項數 | min 0.08 / max 0.67 / **中位 0.25** |
| 封閉性 | 30/30 = `open` |
| 候選集項數 ≤ 2 的畸形條目 | **0** |

**結論：粒度健康，無畸形條目。** 本輪唯一的缺陷是 ⑨-a 的開卷洩漏。

**寫入 README 作為已檢查項**（避免後續重複懷疑）。

### ⑨-f 閉卷後 `zero_direction_precision` 預期會下降 —— 這是真實難度，不是 bug

閉卷下，抽取器要判「沒有域外方向」，必須確認 trace 裡出現的**每一個**方向都在候選集內 ——
比開卷（可以對照域外參考清單）顯著更難。

**提前聲明**：閉卷下該指標下降**不判為抽取器缺陷**。
若下降幅度超出預期，說明的是**閉卷金標的可判定性有問題**（例如候選集描述不夠具體），
需要回頭改金標，而不是放寬門檻。**兩種情況要分清。**

### ⑩-a ★★ M2 门槛双线，取严：**闭卷抽取器 F1 ≥ 0.732**

**同一份基线代码，V5 在开卷拿 0.7321、在闭卷拿 0.0000 —— 差别只在题面里有没有那句话。**

**推论（可作为工具）**：

> **V5 分数 = 题面泄漏探测器。**
> 任何组拿本尺子测自己的系统时，**若 V5 分数异常高，说明他们的 `initial_frame` 泄漏了域外答案**，
> 其测出的所有能力分数都虚高，必须先闭卷改造再重测。

**这是本项目里第一个有明确跨组用途的具体指标**，写入 README 首屏。

两个独立复核给出的项数不同（min 6/中位 9/max 18 vs min 5/中位 8/max 15），原因是**切分规则不同**。裁定：

  零方向条目的比值恒为 0，计入会把 min 压低，是统计污染
- 统一口径后重算一次，记入 README 的「已检查项」

## 补充裁决 ⑫（2026-10-18 第七轮 · 追认 ⑧-a 的规格修补）

### ⑫-a ★★ 四类 status 的精确定义（修订 ⑧-a 的表述，消除自相矛盾）

**Coder 提出并求追认**：⑧-a 的「定义表」与「判定树」在一格上互相矛盾。
**核实成立，追认它的修补。** 矛盾原文：

> 定义表：`not_generated` = 整个 trace 全文无该方向的任何表达
> 判定树：没提到 + 没保留过 → not_generated

**反例**：「方向 X 在中间段被明确否决，最终答案没提它」——
按定义表它不属于任何一类（trace 里有表达 → 不是 not_generated；最终答案没排除 → 不是 selection_failure；
中间段没保留 → 不是 expression_failure）；按判定树它被判 not_generated。
**照字面执行会把「被否决」并进「发现失败」，恰好抹掉这把尺子最想区分的那对失败。**

**修订后的精确定义（取代 ⑧-a 的定义表与判定树）：**

| status | 精确定义 |
|---|---|
| `not_generated` | 整个 trace 全文**无该方向的任何表达** |
| `selection_failure` | 该方向**被明确否决 / 排除 / 搁置**。否决**可以发生在任何阶段**（取舍段或最终答案段） |
| `expression_failure` | 该方向**没有被否决**（活过了筛选），但**最终答案完全未提及** |
| `realized` | **最终答案中**该方向作为可操作选项 / 推荐 / 结论出现 |

**判定树（三分支）**：

```
最终答案里提到它了吗？
├─ 提到了 ──→ 作为可操作选项 / 推荐 / 结论出现？ → realized
│            └─ 明确排除 / 否决 / 推迟？          → selection_failure
└─ 没提到 ──→ 中间段有它的表达吗？
               ├─ 明确被否决 / 排除 / 搁置 → selection_failure
               ├─ 明确保留过（未否决）      → expression_failure
               └─ 完全没有表达              → not_generated
```

**为什么这个表述比 ⑧-a 准确**：

1. `selection_failure` 的判据是「**被否决**」，**不绑定在最终答案段** ——
   这才是「选择失败」的本义（它是在选择环节死的，不是死在表达环节）
2. ⑧-a 理由 3（`expression_failure` 只覆盖「无声消失」）在这个表述下**更成立**：
   `expression_failure` = 活过了筛选却没被呈现，正是「无声消失」
3. 判别式完整：有没有表达 → 被否决了吗 → 最终答案体现了吗。**四类互斥且完备**

### ⑫-b ★ 本次修订对 M2 跑批的影响：零（可追溯）

**必须在 M2 报告里写明**：

> M2 跑批使用修订前的 prompt（判定树两分支版）。
> 复核确认：当前金标 30 条中，**不存在「中间段否决 + 最终答案没提」这一边界条目**
> （`selection_failure` 24 条 evidence 全部落在最终答案段、`expression_failure` 9 条全部落在中间段、
> `realized` 21 条全部落在最终答案段），
> 因此新旧两版 prompt 在本批数据上**行为等价**，跑批结果可直接与金标比对。

## 补充裁决 ⑭（2026-10-18 第九轮 · ★ 两个独立执行体撞同一堵墙）

> 触发：M2 抽取器执行体分片 0 与分片 1 **各自独立**报告了 `in_frame` 不可复现；
> 盲评复核 A / B 报告了 `status` 边界不可复现。**两堵墙都是 spec 的洞，不是执行体的问题。**

### ⑭-a ★★★ 硬约束段的语义拆解 —— 「许可杠杆」必须显式化（新增第 6 类逃逸）

**两个执行体独立撞上的同一堵墙**：

- **分片 0**：「10 条 initial_frame 的【硬约束】都是「在保持 X 的前提下，通过/调整 Y」的模板。
  但 Y 常常**小于**【候选集】… Y 显然不是封闭的「可行解集合」。
  可逃逸测试的五类里**没有「逃出硬约束解空间」这一类**。
  我最后采用的自造读法是：硬约束的 Y 段 = 解空间，X 段 = 禁区。
  这条读法直接决定了我 28 条里约 7 条的 in_frame。」
- **分片 1**：「评估维度里出现某个轴 ≠ 该轴上的方向就是域内；
  只有 FRAME 的候选集里已列有落在该轴上的机制，才判 in_frame。
  同一模式、不同处理，**是我的判断而非 spec 给的**。」

**根因**：初始框架里有**三处知识来源**（候选集 / 评估维度 / 硬约束），
而 spec 只给了逃逸测试的**五个类别**，**每一类该怎么用**没说清。
两个执行体于是各自发明了读法——**两人都合理，但不一致**。

**裁定：拆解【硬约束】段的语义，并新增第 6 类逃逸**

初始框架的【硬约束】段形如「在保持 *X* 的前提下，通过/调整 *Y*」：

> - **X 段 = 禁区**（不得触碰的边界）
> - **Y 段 = 许可杠杆清单**（本框架内**可动**的机制/杠杆）

**in_frame 判定规则（取代 ⑬-b 的表述）**：

| 方向所依赖的机制 | 判定 |
|---|---|
| ∈ 许可杠杆清单（Y 段） | `in_frame = true` |
| ∈ 【候选集】 | `in_frame = true` |
| ∉ Y 段、∉ 候选集、且未触碰 X 段禁区 | **逃出硬约束解空间** = **新增第 6 类逃逸** → `in_frame = false` |
| 触碰 / 违反 X 段禁区 | 域外（但见 ⑭-c 的特殊处理） |

**【评估维度】只是评价轴，不是许可清单** —— 维度上出现过某个轴，**不构成**「该轴在框架内」的证据。

**不要求金标加新段落** —— 许可杠杆从既有【硬约束】段的 Y 段读出，
这样金标模板不必重写（省掉整轮返工）。

### ⑭-b ★★★ 「推迟即弃用」的最终判据（收紧 ⑬-a 之外的 status 边界）

**盲评复核 A / B 的分歧全部集中在这一条**，两者独立得出同一诊断：

- A：「若金标的 selection_failure 明显更少，很可能是「**推迟是否等于弃用**」这条口径需要统一」
  （金标 24 vs A 29 vs B 27 —— **金标比两个复核者都少**）
- B：不确定的 5 条里，G11-1 / G03-1 / G25-2 全是「推迟 vs 落地」这一族

**裁定：「推迟即弃用」的操作化判据**

> **看最终答案里该方向有没有产生「当下能执行的动作」。**
>
> | 最终答案里该方向… | 判定 |
> |---|---|
> | 给出**当下可执行**的动作（试点 / 本月启动 / 去谈 / 调参数 / 落成规则） | `realized` |
> | 只列为**议题 / 未来事项 / 推后到下一阶段 / 转交他人 / 下轮再议**，**无当下动作** | `selection_failure` |
>
> **不再依赖具体措辞**（"不落地" / "暂不" / "不采纳" 之类词表）——
> 判据是**结构性的**：有没有当下动作。

**为什么这比措辞词表好**：A、B、金标三方都指向"措辞"判据，结果三方不一致
（最终答案里有的写"暂不做"有的写"推到 2027"有的写"建议这次一并去谈"）。
**结构性判据不随措辞变。**

**配套：允许最终答案自述** —— 若答案明写「它不改变本次技术路径」这类自述，
说明该方向**没有产生当下动作** → `selection_failure`。

### ⑭-c ★ not_generated 与「违反禁区」必须分开（执行体分片 0 的第 ③ 点）

**分片 0 的问题（成立）**：

> 我报出的 11 条 not_generated 里有 8 条是**直接违反硬约束**的…
> 按「违反硬约束 = 逃出边界 = 域外」处理，代价是**任何根本性杠杆都会被报成 not_generated**
> （假阳性风险集中在这一批）。not_generated 是否只收「帧内可行但没生成」的方向？

**裁定：分开**

| 方向性质 | 归属 |
|---|---|
| 逃出许可杠杆解空间（∉Y、未碰X） | 可报为 **域外方向**；若 trace 全文没它 → `not_generated` |
| **触碰 / 违反禁区（X 段）** | **不报为 `not_generated`**。归入**独立诊断桶** `constraint_violation_candidates` |

**理由**：`not_generated` 的语义是「**本该被想到的域外方向**没被生成」。
一个**根本不该出现的不可能方向**（违反禁区）不是"本该被想到"，报进去会让
`not_generated` 退化成「检测违规」，与「发现失败」混淆。

**但违反禁区的方向是极有价值的信号** —— 单列为独立诊断量：
- `constraint_violation_candidates`（**不进任何召回统计、不进主表 F1、不进门槛**）
- 它对 A 组那类「约束建模」场景直接有用：**模型系统是否偷偷违反了自己声明的边界**

### ⑭-d ★ 三分类的可复现性分级（写进报告，不得混为一谈）

盲评复核三方分布：

| status | 金标 | 复核A | 复核B | 可复现性 |

## 补充裁决 ⑯（2026-10-18 第十一轮 · ★ 一个静默算错，以及它带来的教训）

### ⑯-a ★★★ 门槛定版：**闭卷·主表口径 ≥ 0.6106**（⚠️ **本条已被 ⑯-e 取代 → 0.6749**，见下）

金标构造方在修复自己的基线实现时，**查出了自己代码里一个静默算错的 bug**：

```
fp / tp_f / fn_f / fp_f 是逐条覆盖（= 最后一条的值），不是累加
```

**后果**：闭卷基线 F1 一度报成 **0.9381**（真值 **0.5106**）——
**虚高近一倍，且没有任何报错**。

**这个 bug 的危险性在于它的失败模式**：报错你会去查，**"报出来的数比该数大"你只会当成好消息**。
金标构造方自己说：「我第一次看到 0.938 就该怀疑，而不是当成好消息」。

**修复后的双口径数（新 CSV 直接计算，856 行）**：

| 口径 | 闭卷（主指标） | 开卷（对照） |
|---|---|---|
| **主表口径**（分母 54，与抽取器同口径） | **0.5106** | 0.7664 |
| 含漏判口径（分母 59，历史口径） | 0.4932 | 0.7321 |

**闭卷最佳行明细**：`tp=36 fp=51 fn=18 · P=0.4138 R=0.6667 F1=0.5106`
→ 注意 **precision 仅 0.414、fp 高达 51** —— 词法基线**过度声称极其严重**。

> **★ M2 最终门槛 = 0.6106**（= 0.5106 + 增量 0.10）
> **★ 上界报警线 = 0.7664**（开卷·主表口径）
> **★ 泄漏的价钱 = 0.2558**（主表口径；含漏判口径是 0.239）

**作废值**：0.5932（跨口径）、**0.6714**（继承旧 CSV 的错误 `fp` 列）。

### ⑯-b ★★ 「口径自检」必须固化进代码，不能靠人看数

金标构造方在修复 bug 后，**把口径不变式写成了 assert 并固化到每次扫描**：

```
assert tp + fn == 54        # 主表分母 = 非 not_generated 的金标方向数
assert fp + 已匹配数 == 预测总数
assert tp_f + fn_f == 59    # 含漏判分母
```

**C 组主会话独立复跑这三条不变式（新 CSV，856 行）：0 行违反 ✅**

**裁定（写进 spec 硬规则）**：

> **任何打分函数都必须自带口径不变式断言，且断言必须随函数一起被测试覆盖。**
> **「报出来的数比该数大」是最危险的失败模式** —— 报错会被查，虚高不会被查。
> 数字看起来漂亮时，**先查不变式，再谈结论**。

**这与 ⑭-e 的「每条断言必须配反向测试」是同一族规则的延伸**：
断言要有效，**计算它的函数也要自带不变式**。

### ⑯-c ★ 「三个数不一致」本身是信号，不是噪音

本轮出现过三个基线值：**0.5397（我，从旧 CSV 复算）/ 0.5714（Coder，从旧 CSV 转换）/ 0.5106（真值）**。

前两个都**不是随机误差** —— 它们**系统性地继承了同一个错值**（旧 CSV 的 `fp` 列）。

> **当同一份数据经三条独立路径得出三个数时，不要取平均、不要取最高、直接去找出哪一个的输入是脏的。**
> **系统性偏差不会用取高/取平均消除。**

**裁定**：M2 报告里**必须写明这组三个数及其来源**（含两个作废值），
**这是「独立复算」这条纪律的实际价值** —— 如果只有一条路径，0.5714 会被当成事实写进门槛。

### ⑰-b 新增逃逸子类型：「推翻 / 改写 FRAME 所依赖的前提」

G24-② 与 G25-② 都是「方向与候选集**方向相反**」或「**推翻候选集赖以成立的前提**」，
这类在 ⑭-a 的六类逃逸里没有显式位置（它既不是"新候选"也不是"新维度"）。

> **新增第 7 类逃逸（子类型）：推翻 / 改写 FRAME 所依赖的前提。**
> 判据：若该方向的实现会使【候选集】里某一项**不再成立**（它假设存在的东西被取消/被改写）
> → `in_frame = false`。
> 反之，若方向只是**在候选集既有假设之内**取不同取值 → 域内。

**同时记入已知局限**：这两条的**「可报性弱」** ——
候选集里存在相近措辞（"媒介范围…拆分"、"在既有…条件下"），
闭卷抽取器读到会判成域内 → **不会报** → 假阴性。
**这是金标可报性问题，不是金标错误**，但必须在报告里写明。

### ⑰-c ★★★ 闭卷基线过度声称的成因查清了 —— 结论与预期相反

**C 组主会话问**：闭卷基线 `fp=51` 是不是"违反禁区"类方向？
**金标构造方实测全部 51 个 FP 的分布，答案：不是。**

**实测发现**：那些 FP **几乎全是明摆着的域内候选**，只是**措辞与候选集零字面重叠**：

| 条目 | FP 是什么 | 候选集怎么写的 | 二元组重叠 |
|---|---|---|---|
| G26（5 个 FP） | 座位轮换 / 支持清单 / 家长群公开课 / 结构化登记 / 班主任带教 | 「班级与座位的组织形式…行为记录与支持机制…家校沟通渠道…记录的可执行性」 | **0.000–0.034** |
| G03（3 个 FP） | 读侧视图层 / 防腐层 / 并行泳道 | 「数据契约、依赖治理、发布批次」 | ≈0 |

**结论（与预期相反）**：

> **闭卷基线的过度声称来自「候选集用抽象术语、trace 用具体动作」的词汇错配，
> 不是「把不可能方向报出来」。**
>
> ⟹ **这把尺子的风险点不是"禁区不清"，而是"框架表述与 trace 表述说不上话"。**
> ⟹ **对 A 组的建议方向要改**：不是「加更多硬约束」（那会**增加**禁区类候选、
> 把召回口径搅浑），而是**「让【候选集】用与 trace 候选相同的词汇写」**，或让抽取器做语义匹配。

**这条同时给出了一个重要的跨组预警**：

> A 组（multi-mind）的 M 层若用抽象术语描述约束/候选，
> **它自己的 N1 关联发现也会漏掉具体动作** ——
> 这与 A 组的「香港」问题是**同一类**（框架与语料说不上话），只是发生在不同环节。

**并解释了 ⑯-d 的 precision 0.414 / fp 51**：
词法基线在闭卷下的失败模式是过度声称，而主表 F1 同时惩罚 FP，
**所以主表口径天然偏好精确** —— 这与「主表口径比含漏判口径更适合当门槛」是同一理由。

**这条要写进 M2 报告的第一屏。**

## 补充裁决 ⑱（2026-10-18 第十三轮 · 门槛口径最终定版）

### ⑱-a 四个基线数现在全部归位，性质分三类

| 数 | 性质 | 处置 |
|---|---|---|
| 0.9381 | **脏**（General `score()` 的 fp 逐条覆盖 bug） | 作废 |
| 0.5397 / 0.5714 | **脏**（从旧 CSV 转换，继承同一个错 fp 列） | 作废（⑯-c 已述） |

| **0.5397 @0.34 / 0.5714 @0.20** | 干净，**评测器自己的路径**（scorer + Jaccard matcher） | ✅ **规范口径** |

**Coder 的核心论证成立，采纳**：

> 门槛比较的是「抽取器 F1 vs 基线 F1」，**抽取器 F1 由评测器算**。
> 基线若用另一套打分器算，两者就不是同一个量 —— 门槛就没有意义。
> **我倾向 (a)，理由不是「门槛越严越好」，而是 (b) 下门槛比较的不是同一个量。**

**所以 General 的 0.5106 不作门槛**（它用 General 的 `score()`，与评测器算抽取器 F1 的路径不同）。
但 General 的新 CSV **仍是重要的数据源**（域外判定方式的变体扫描），只是不能直接当门槛基准。

### ⑱-b ★★ 匹配阈值敏感曲线（C 组主会话独立复算，评测器路径）

```

 0.25       0.5714     0.5000  0.6667   0.4593
 0.30       0.5714     0.5000  0.6667   0.4593

 0.46       0.4603     0.4028  0.5370   0.3852
 0.50       0.4603     0.4028  0.5370   0.3852
 0.55       0.4286     0.3750  0.5000   0.3556

**这是本项目测到的最敏感的一个参数** —— 比 oof_thr（0.5106→0.5397 跨度 0.03）大一个数量级。

**裁定：主门槛用评测器默认阈值 @0.34，不取最松阈值。**

理由：
1. **同口径**要求**完整协议一致**（scorer + matcher + **阈值**）。
   允许基线挑最有利的阈值、而抽取器用默认阈值，就是⑯-c 精神的延伸 —— **不对等**。
2. 评测器的默认协议就是 @0.34，**抽取器也按这个协议被评**。
3. 若要"取最严"，正确做法是**抽取器与基线在所有阈值上都比、取最不利点** ——
   那会要求抽取器在最不利的匹配阈值下也赢，**门槛将失去意义**（匹配阈值不是能力）。

### ⑱-c ★ M2 门槛：主门槛 + 强通过线（两线都报）

> **主门槛（通过条件）：闭卷抽取器 F1 @0.34 ≥ 0.6397**（= 基线 @0.34 的 0.5397 + 0.10）
> **强通过线（附加参照）：≥ 0.6714**（= 基线在最松阈值 @0.20 的 0.5714 + 0.10）
> → 达到强通过线 = **连「基线调参后的最优词法对手」都超过**

**并且 M2 报告必须给出抽取器在整条阈值曲线（0.20–0.60）上的 F1**，
不只是 @0.34 一个点 —— **因为这个参数跨度 0.2381，单点数字没有意义。**

### ⑱-d 「取高」原则的适用范围收窄（重要）

⑨-c 定的「门槛基准 = max(所有基线变体 × 所有阈值）」**过宽**，现修正为：

| 类别 | 是否取最高 | 理由 |
|---|---|---|
| **变体**（V1–V8：不同的域外判定**方法**） | ✅ 取最高 | 基线可以**换一种方法**，那是不同的对手 |
| **参数**（oof_thr / match_thr / stance_thr：同一方法的**调参**） | ❌ **不取最高** | 取最高 = 拿「基线调参后的最优」比「抽取器默认参数」，**不对等** |

**这条修正同时作废 Coder 的「规范基线 = 0.5749（@0.2）」作为门槛的做法** ——
但**该数保留为「最努力的词法对手」参照**，进强通过线（⑱-c）。

### ⑲-a ★★ 「只在最终答案出现的域外方向」怎么算（分片 0 第 5.6 点）

**执行体报告的冲突**：

| 判据 | 用哪段语料 | 作用 |
|---|---|---|
| 「这个方向**被 Agent 生成过**吗」 | **只算中间段**（方向生成 / 取舍段） | 决定它是不是 trace 里的既有方向 |

**并给「只在最终答案出现」的方向一个正式身份**：

> **综合阶段新引入（`introduced_in_synthesis`）**：
> 若某域外方向**只出现在最终答案、中间段没有**，
> 说明它是在**综合阶段新产生**的 —— **这恰恰是这把尺子最该测的能力**
> （Agent 能不能在收敛过程中自己长出新方向）。
>
> - 它**算被生成了**（不是 not_generated）
> - `evidence_quote` 引最终答案原话
> - `status` 按最终答案对它的 stance 判
> - 报告里**单列计数** `introduced_in_synthesis_count`
> - **防滥用条款 8 改写为**：不许把最终答案的表述当成该方向在**早期阶段**被生成的证据；
>   但最终答案独有的域外方向是**真实的能力体现**，不禁止报告。

**这比原来的防滥用条款更有价值** —— 原来它防的是"用答案冒充过程"，
现在它同时**保住了一个真正想测的指标**。

### ⑲-b ★★★ 「保留」与「搁置」必须分开（分片 1 第 5.1 点 —— 6 条 status 的系统性风险）

**执行体报告的冲突**（它自己发现了）：

> 本 shard 有 6 条「中间段写『保留…』、明确带推迟措辞、最终答案完全未提」的方向。
> 我一律判了 `selection_failure`。
> 但规则 ② 的「没提到」分支写的是「中间段明确保留过（**未否决**）→ expression_failure」，
> 字面上会把这 6 条判成 expression_failure。**这两处规则文本互相冲突。**

**核实：真冲突。而且分片 1 的判断是对的。**

**裁定 —— 明确「保留」与「搁置」的区分**：

> | 中间段对该方向… | 最终答案 | 判定 |
> |---|---|---|
> | **明确保留、无否决/搁置措辞** | **完全未提** | `expression_failure`（**活过筛选，却在合成时丢了**） |
> | **带推迟 / 搁置 / 否决措辞**（「保留为待议」「下轮再议」「暂不推进」） | 提不提都算 | **`selection_failure`**（**方向本身被否决了**） |
> | 明确保留、无搁置措辞 | 作为选项/推荐/结论出现 | `realized` |
> | 明确保留、无搁置措辞 | 明确排除/推迟 | `selection_failure` |
> | 完全没有表达 | — | `not_generated` |
>
> **关键**：⑮-b 去模板化之后，EF 的措辞已不再统一，
> **这个区分必须靠语义（"它是被搁置还是被保留"），不能靠关键词**。

**为什么这么裁**：⑭-b 的判据是「**当下可执行的动作**」。
一个被明确搁置的方向**没有当下动作** → 它**被否决了** → `selection_failure`。
`expression_failure` 的语义是「**活过了筛选却没被呈现**」——
**「活过筛选」的前提是它没被否决**。被搁置 = 被否决。

**对本轮数据的影响**：
- 分片 1 的 6 条**判对了**（按此裁决仍是 `selection_failure`）→ **不需要重跑**
- 但 **prompt 文字有歧义**，必须改（下一轮跑批用新版）

### ⑲-c ★★ X 段（禁区）的判定规则必须明确（分片 0 第 5.1 点）

**执行体报告的问题**：

> G01/G04/G10 的硬约束都是「在…内/框架内」的**边界式**写法，没有「保持 X 不变」句式，
> spec 没规定这种写法怎么拆 X/Y。
> 若 spec owner 认为边界式硬约束的边界本身即禁区，
> G01 的 ⑥/⑤ 与 G04 的 ③ 要翻成 true（本批 9 → 12）。

**裁定：X 段（禁区）的判定规则**

> - **X 段 = 被点名保护、不得改变的对象**。
> - 方向是否构成 `constraint_violation`，判据是
>   **该方向是否直接改变了 X 段所保护的那个对象**。
>   - 改变「法人实体不变」→ violation
>   - 改变「现行同行评审流程内」→ violation
>   - 与被保护对象**正交**（如认证周期 vs 资产所有权）→ **不**是 violation，
>     只算第 6 类逃逸（逃出解空间）
> - **边界式硬约束**（「在…内 / 框架内」）：边界本身即禁区，
>   但**只有当方向明确越出该边界时**才算 violation。
>   判据：trace 或 initial_frame **明说**越界（如「超出运维合同范围」）才计；
>   仅仅"用了边界外的机制"而未越界 → 第 6 类逃逸，不计 violation。

**这条同时是评测器侧的风险控制点**：
`constraint_violation` 的方向会被**排除出主表**，
**若该判定过宽，会把真方向排掉、虚高 F1**。
所以「X 段判定过宽」不只是标注问题，**会直接污染 M2 的主指标**。
**必须在报告里报出 `constraint_violation_count` 与逐条明细**（Coder 已实现该桶）。

### ⑳-a ★★★ 根因找到了：计分池口径（不是随机误差，也不是"三种合法定义"）

> **我的基线当时没清空** —— 那 5 条零方向条目（G26–G30）上的 **15 个预测被算进了主表 FP**

### ⑳-b ★★ 撤回 ⑱-d「参数不取最高」—— 我推论过头了

**⑱-d 我写的是**：「同一方法的**调参**不取最高 —— 取最高 = 拿『基线调参后的最优』比『抽取器默认参数』，**不对等**」。

**这个推论有个漏洞**：不对等只发生在「基线用阈值 A 的成绩、抽取器用阈值 B 的成绩」。
**只要抽取器也在同一个阈值点上被评分，就是同点比较，就是对等的。**

**裁定（取代 ⑱-d）**：

> | 类别 | 是否取最高 | 理由 |
> |---|---|---|
> | **变体**（V1–V8：不同的域外判定**方法**） | ✅ 取最高 | 基线可以换一种方法，那是不同的对手 |
> | **参数**（oof_thr / **match_thr** / stance_thr） | ✅ **取最高** | 只要**抽取器在同一阈值点上被评分**，就是同点比较 |

> **前提**：门槛判定与抽取器评分**必须使用同一匹配阈值**。
> 若抽取器在多阈值上取最优再与门槛比 → 不对等，**禁止**。

**所以 ⑱-c 的两级门槛作废**，改为单一门槛 + 全曲线报告（见 ⑳-c）。

### ⑳-d ★★ 计分池口径必须写进规范（这是第三次栽在口径上）

## 补充裁决 ㉑（2026-10-18 第十六轮 · ★ 漏判召回不可度量 → 一个新的探针设计）

### ㉑-a ★★★ 事实：闭卷金标上 `not_generated` 几乎无法构造（三面围堵）

金标构造方报告的后果：**主 `miss_detection_recall` 分母 = 0**，
4 条 `not_generated` 全部落进「抽取器没有义务发现」的桶。

**根因链（自洽，且是结构性的）**：

> 要构造一条「抽取器应当能报出」的 `not_generated`，必须**同时**满足三条：
> ① **闭卷可从题面推出**（否则抽取器没有线索）
> ② **不被候选集措辞遮蔽**（否则抽取器读到会判成域内 → 不报）
> ③ **不触碰禁区**（否则它根本不该出现）
>
> **本集里一条都没有。** 4 条候选漏判方向的归属：
> - 1 条违反禁区（不可能出现）
> - 2 条 `gold_author` 主观产物（只有作者知道该想到什么）
> - 2 条「推翻候选集前提」（候选集含相近措辞 → 闭卷读到会判成域内 → 不报）

**这不是抽取器不行，是靶子不可达。**

### ㉑-b ★★ 普适结论：任何「域外方向」框架的评测集都有这个结构性盲区

> **在「域外方向」框架下，`not_generated` 这一类在闭卷 + 严格 in_frame 定义下几乎不可构造。**
>
> 三面围堵：
> ① 违反禁区 → **不该报**
> ② 标注者主观产物 → **不公平**
> ③ 被候选集措辞遮蔽 → **结构上不可报**
>
> ⟹ **除非专门设计「题面给了线索、但方向确实域外」的任务，否则漏判召回测不出来。**

**这条不是本项目的个案，是「问题空间构建」这类评测的通用陷阱**，必须写进主报告的方法论章节。

### ㉑-c ★★★ 新探针：前提识别能力（Premise Recognition Probe, PRP）

**思路**：不从「正例」里挖漏判，而是**从 trace 与框架的落差里自动生成**。

> **对每道题：**
> 1. 从【候选集】识别出它**依赖的隐含前提** P
>    （例：G12 的候选集默认「需求按计划推进」；G26 默认「座位按现有名单分配」；
>    G21 默认「用工/排班制度不变」）
> 2. 检查 trace **有没有按 P 走**
> 3. **若没有 → 「推翻 P」本身就是该题的一条域外方向**
>
> **这条方向是闭卷可报的** —— 因为抽取器能从 trace 与框架的**落差**里自己发现它，
> **不需要金标事先枚举**，也不需要作者主观指定。

**它一次性解决两个问题**：
1. **主召回分母不再是 0** —— PRP 能为每道「trace 违反了前提」的题自动产出 1 条
   `not_generated` 金标，**且这些是真正"抽取器应当能报出"的**（三条条件天然满足：

## 补充裁决 ㉒（2026-10-18 第十七轮 · ★ PRP 的产出条件修正 + 三探针分解）

### ㉒-a ★★★ 修正：PRP 产出 `not_generated` 的条件比原设想严格得多

**金标构造方抽检 8 道题后的发现（成立，且是本项目目前最关键的一处自我修正）**：

> 每一道「trace 违反了前提 P」的题，**trace 都在阶段 3 提出了对应的域外方向**
> （因为合成 trace 就是按「违反前提就必须提出」造的）：
> G01 违反（分批交付/仓单质押）→ trace 提了 ④⑤ → 金标里是 realized 域外方向；
> G13 / G16 / G05 / G20 同理。

**⟹ PRP 产出 `not_generated` 的真正条件是**：

> **「trace 违反了 P，但从未提出推翻 P」**

**不是**「trace 违反了 P」。**前者比后者稀有得多。**
在本集上，**凡违反前提的题 trace 都提了 → PRP 探针 C 的产出 ≈ 0**。

**这不否定 PRP 的价值，但决定了三件事**：

1. **本集上探针 C 无产出，是「合成 trace 的构造产物」，不是方法失败** ——
   金标构造方造 trace 时遵循「违反前提就必须提出」，**这个构造规则本身消灭了 PRP-C 的靶子**。
2. **探针 A（前提识别）在本集完全可跑** —— 它的金标就是那 30 条前提清单。
3. **探针 B（违背检出）在本集完全可跑** —— 因为 P 是**给定的**。

### ㉒-b ★★ 三探针分解：把「前提识别」从被计分的路径挪到被给定的路径

**这是对 ㉑-c 主观性软肋的干净解法**（金标构造方提出，采纳）：

| 探针 | prompt 给什么 | 问什么 | 测的是 | 计分方式 |
|---|---|---|---|---|
| **A 前提识别** | 只有题面 + 框架 | 「候选集依赖的隐含前提是什么？」 | 能不能**说出** P | 与金标 P 做**等价性判定**（人工/模型） |
| **B 违背检出** | **P 直接给在 prompt 里** | 「trace 有没有按 P 走？」 | 能不能发现落差 | `follows` / `violates` / `unclear` |
| **C 逃逸方向生成** | P + 落差位置 | 「由此产生的域外方向是什么？」 | 能不能**命名**逃逸方向 | 与金标方向**同点比较** |

**关键收益（三条）**：

1. **B/C 把 P 给出去 ⟹「推翻 P」成为闭卷可报的合法靶子**
   → **主召回分母不再为 0**（新增 `expected_source = "prp"` 桶，**进主统计**，
   因为前提是给定的、落差可定位 —— 满足 ㉑-a 的三条条件）
2. **「前提识别」这个能力被单独隔离在探针 A**，不再污染 B/C 的计分
3. **㉑-c 那个「两个分量」有了可操作的分工**：
   **前提识别率 = 探针 A 的分 · 前提违背检出率 = 探针 B+C 的分**

### ㉒-c ★★ PRP 作为金标的独立复算器（本集已实测 5/5 一致）

5 条零方向条目，PRP 的预测与金标**完全一致**：

| 条目 | 候选集依赖的前提 | trace | PRP 预测 | 金标 |

| G26 | 课堂问题的解法在「班级组织形式+家校沟通+行为记录」内 | 按 P 走 | 无「推翻 P」方向 | **零域外方向** ✅ |
| G27 / G28 / G29 / G30 | 协商分摊+施工 / 科目排序归口 / 产能质量联合管理 / 估算拆分记录 | 按 P 走 | 无 | **零域外方向** ✅ |

**5/5 一致，且这条验证路径与金标构造完全独立** ——
它用的是「前提—trace 落差」，不是「方向是否出现」。

**⟹ PRP 可以当作金标的独立复算器**：将来任何一条金标方向被质疑，
可用 PRP 复核一遍（「trace 有没有偷偷越出候选集的前提」）。

### ㉒-d 前提清单的 schema（采纳金标构造方的建议）

```
id, premise, trace_follows_premise (true|false|partial), basis,
+ premise_raised_in_trace : true|false    ← trace 是否已提出推翻 P
                                           （决定它属 PRP-not_generated 还是已有域外方向）
+ candidate_overturn_dir  : str|null      ← 若已提出，抄下那条方向原文（与金标方向对照）
+ premise_kind            : 资产归属|承诺机制|考核口径|流程前提|数据前提|…
```

**`trace_follows_premise` 用三值**（true / false / **partial**）——
本集至少有 G05③（当期立项评估）、G10⑤⑥ 等「部分遵守」的中间态，两值会丢信息。

### ㉒-e 前提撰写的 5 条风险控制（硬约束，违反即作废）

1. **P 必须写成「关于世界的信念」，不能写成候选集某一项的复述**
   —— 否则「违反 P」退化成「换了个说法」，变成同义改写题。
2. **违反点必须可定位到 trace 的具体段落** —— 定位不到就不算违反。

5. **前提与域外方向要一一对应可追溯** —— 每个 PRP 方向应能说出「它推翻了 P 的哪一部分」。

### ㉓-b ★★ 三次调度失误的共同结构

| # | 失误 | 表现 | 装了什么防线 |
|---|---|---|---|
| 1 | **渲染早于改 trace** | prompt 里是旧措辞，抽取器引用在新金标里查不到 → 被误判为「编造」 | **版本锁**：manifest 记金标 md5 + system.txt sha，评分前强制校验 |

**因此新增一条通用纪律**：

> **凡是「通过存在性检查」得出的结论，都必须再过一次「同一性检查」**
> （版本 / 轮次 / 时间戳 / 内容哈希），**否则不作为证据**。

### ㉓-c ★★ 新硬闸门：evidence 可核率 < 100% 即中止，禁止跑分

**装在 `run/collect_and_score.py`（评分入口）**：

> 独立校验若发现 **任何一条** evidence 不可核（编造 或 prompt 与金标版本脱节），
> **立即中止并拒绝跑分**，报：
> 「可核率是跑分的前置条件 —— 先查清是『抽取器编造引用』还是『prompt 版本过期』，
> 两种情况的处理完全不同，禁止在此状态下出分。」

**为什么它比时间戳校验更本质**：
时间戳校验只能抓「版本错配」这一种；**可核率抓的是所有会让分数失真的引用问题**
（编造、截断、改写、版本脱节、语料口径不一致）。

**复现验证**：把第二轮产物放回 `preds/` → 闸门直接中止 ✅（本次事故已被自动拦住）

**主会话本次的实际错误顺序**：
1. 独立校验报了 9 条不可核 ← **这是明确的告警信号**
2. **但我直接接着跑了 M2** ← 错误
3. 直到跑完分、看到 FAIL，才回头查 mtime 才发现是错配

**裁定**：

> **独立校验的输出是跑分的前置条件，不是跑分之后的附注。**
> 校验有任何硬伤 → **先查清，再决定要不要跑分**。

**这条已由 ㉓-c 的代码硬闸门强制**（不再依赖人的判断顺序）。

### ㉓-e ★★ 第 4 次「假通过」的规律提炼（同一族问题的完整分类）

| # | 现象 | 所在层 | 失败特征 |
|---|---|---|---|
| 1 | `fp` 逐条覆盖 | **计算层** | 算出一个**更大**的数，不报错 |
| 2 | 旧 CSV 继承错值 | **数据层** | 继承脏值，不报错 |
| 3 | 池口径不一致 | **口径层** | 两类东西**混算**，不报错 |
| 4 | `prp` 不在 `EXPECTED_SOURCES` | **枚举层** | 该类数据**静默落到默认桶**，不报错 |

**第 4 类最隐蔽的原因**：它是「按类别分流」的逻辑，**漏了一个枚举项**，
于是那个类别的数据**全部静默落到默认分支**。
系统看起来完全正常——没有异常、没有告警、数值也在合理范围——
**只是两类东西被混在一起算了。**

**通用防御（写进硬规则区）**：

> **凡存在「按类别分流」的逻辑，必须有两条断言：**
>
> ① **可达性断言**：每个预期类别都真的能路由到
>    （**枚举集合 ⊆ 实际可达分支集合**）。
>    只测「有数据时是否正确分流」是不够的 ——
>    第 4 次 bug 的本质就是**降级路径吞掉了本该走主路径的数据**。
>
> ② **降级显式化**：类别未定义时的降级行为必须是**显式声明**的，
>    **且在报告里可见**（给出计数与逐条理由）。
>
> **因为静默降级会让两类东西混算，而混算的结果看起来完全正常。**

**配套的具体要求（交给评测器）**：

> 报告必须显示 **「有多少方向因 `expected_source` 未定义 / 未知而进了主桶」**。
> 这个默认行为（未标注 = 应当能发现 = 进主分母）**必须是可见的计数，不能是隐式的**。
> 若该计数 > 0，须在报告里标 `unknown_source_in_main: N` 并逐条列出。

**这一族四条事故的共同教训（一句话版）**：

> **不报错 ≠ 算对了。**
> 本项目至今所有最贵的错误，都长成「**结果看起来完全正常**」的样子：
> 虚高一倍的基线、继承来的脏值、混算的池、吞掉主路径的降级分支。
> **因此每一个数字都必须能回答：「如果它错了，警报在哪？」**

## 补充裁决 ㉔（2026-10-18 第十九轮 · ★ 修正 ㉓-e：四类事故要按「失败方向」分类）

> **本条取代 ㉓-e 的四行表**（金标构造方指出的修正成立：混着说会丢诊断价值）。

### ㉔-a ★ 四类「假通过」按失败方向分类

| 次数 | 症状 | **失败方向** | 人会怎么反应 |
|---|---|---|---|
| ⑯-b | `fp` 逐条覆盖 | **报得比实际好** | 当成好消息（「0.9381 比基线高多了」） |
| ⑰-e | 旧 CSV 继承错值 | **污染下游** | 两个数一起错，且各自看起来合法 |
| ⑳-a | 池口径不一致 | **量的不是同一个东西** | 取平均 / 取高（⑯-c 明令禁止） |
| ㉓-c | 分支永不进入（枚举漏项） | **那段逻辑从未被执行** | 「通过」是假的，**且正确与否与真实结果无关** |

**为什么必须按方向分类**：四者的**误判方式**不同，因而**被发现的方式**也不同 ——
- 前三种在**数值层面**露出来（数字对不上）
- 第四种在**行为层面**露出来（数字全对，但那段逻辑是装饰品）
  → **只做数值交叉验证，永远发现不了第四种。**

### ㉔-b ★★ 通则（比"四类"更重要）

> **任何检查 / 分支，至少要有一条真实数据路径能走进去。**
> **走不进去的分支 = 装饰品**：「通过」与否与真实结果无关。
>
> **反制（两条，必须都做）**：
> ① **合成用例 / 随机维度**：强制点亮真实数据到不了的分支
> ② **显式列出「哪些分支在真实数据上恒不触发」** —— 不藏

**本项目已命中的恒不触发分支（须在 M2 报告里写明）**：

| 分支 | 状态 | 其正确性由什么保证 |
|---|---|---|
| **主召回桶 `main`** | 本集 4 条 not_generated 全在单列桶（author_only 2 + low_reportability 2）⇒ **main 桶在真实数据上恒为 0 条** | **仅由合成用例保证，不由真实数据保证** |
| **`punct` 三档** | 54 条全 exact ⇒ punct 档恒为 0 | 同上 |

**⟹ M2 报告必须写明**：
> 本集上「主召回桶」与「punct 档」的**正确性由合成用例保证，不由真实数据保证**。
> 不得让读者以为它们被真实数据验证过。

**这是一条诚实性要求，不是技术缺陷。**

### ㉔-c ★★ M3 素材：能不能通过「改题面」把 gold_author 类转成可推的？（新方向）

金标构造方提出的观察，**我认为是本轮最有启发性的一条**：

> 本批有两条 `gold_author` 的 not_generated，本质上也是「推翻前提」方向 ——
> 它们与 PRP 的差别**只在于 P 是标注者事后认出的、不是从题面能推的**。
> - 其中一条的 P（形如「我方对自己作品的权利归属是完整清楚的」）在题面里**没有任何线索**
>   → **按定义只能是 `gold_author`**
> - 另一条的 P（形如「某类风险由我方单边承担」）**题面给了成本结构**

### ㉖-b ★★ 候选集条目与禁区前提冲突时谁优先（第三轮分片 2 提出的最高不确定项）

**问题**：G27-①「把『全楼一致同意』改为双重表决口径」——

> 禁区（X 段）是「**不得触碰的边界**」，它比候选集（「常规解空间」）**更强**。
> **候选集条目与禁区冲突 → 那一条候选集条目本身是无效的**
> （它的存在依赖于禁区）→ 该方向**推翻了一个已失效的前提** → 第 7 类逃逸，域外。

> **且**：若该方向**改写了禁区所保护的那个申报前提** → 额外设 `constraint_violation = true`。
> **保守条款（承 ⑲-c）**：若只是「擦边」、trace 未明说改写了禁区 →
> **不记 CV**，但仍可判第 7 类域外。

### ㉖-c ★★ 「引入第三方机构/中介」这类常见机制归不归 FRAME（spec 原无规则）

**问题**：分片 2 遇到 G24「第三方采光影响评估」（判域内）vs G29「第三方追溯/召回」（判域外），

**裁定：判据不是「新不新」，而是「FRAME 有没有假设这件事由内部解决」。**

> - 若 FRAME 的【候选集】或【许可杠杆】里已隐含「可引入外部方」

> - 若 FRAME 假设「**这件事由我们自己内部解决**」，而方向是「让外部机构进来」→

### ㉖-d ★★ 开放性 = `open` 时，第 6 类逃逸是否随「新候选」一起失效？

## 补充裁决 ㉗（2026-10-18 第二十一轮 · ★★ 开卷对照的用途收窄，与「泄漏代价」的精确读法）

### ㉗-a ★★ 开卷对照的结论（20 题同题对比，开卷 2 片 / 闭卷 3 片）

```
闭卷  51 条: realized 13 · selection_failure 34 · expression_failure 1 · not_generated 3
开卷  58 条: realized  9 · selection_failure 40 · expression_failure 0 · not_generated 9
                              → 开卷多报 7 条
   差值构成: not_generated +6 · selection_failure +6 · realized −4 · expression_failure −1
```

### ㉗-b ★★★ 泄漏的代价不是「更准」，是「把方向报在错的位置」

**两个方向同时发生**：

| 现象 | 机理 |
|---|---|
| **not_generated +6** | 题面给了「域外参考」清单 → 抽取器**从清单里读到了"答案"**，但这些方向在 trace 里**根本没出现** → 报成「**该想到而没生成**」 |
| **realized −4** | 清单吸走了注意力 → 抽取器**反而漏了 trace 里真正被综合阶段新产生的方向** |

**⟹ 结论（反直觉，且必须写进报告）**：

> **开卷（题面泄漏答案）不会让 Agent 更会发现方向。
> 它会让 Agent「看起来更会发现」，但方向是错的 ——
> 报在 `not_generated` 而不是 `realized`。**

**⟹ 因此，用开卷金标评测「域外方向发现能力」会得到一个虚高且方向错误的分数，
而这个错误恰好表现为「看起来在批评 Agent 漏了方向」——
会让评测方误以为被测系统有个方向性缺陷。**

**这解释了为什么闭卷改造是必须的**（⑨-a）：闭卷下抽取器只能从 trace 里找方向，
报出来的 `realized` 是真实的。

### ㉗-c ★★ 开卷对照的用途收窄（它测不了什么）

**开卷的「域外参考」段在语义上是「被明确排除的方向清单」，不是「答案清单」。**

⟹ **开卷对照不能用来测漏判召回（recall）**：
- 那些方向**Agent 没提是正确的**（提了反而是越界）
- 分片 0/1 的开卷执行体都独立得出了这一判断
- **开卷组报出的 `not_generated` 应当视为「对泄漏的过度反应」，而不是「发现失败」**

**⟹ 开卷对照的唯一有效用途**：

| 用途 | 有效？ |
|---|---|
| 测「题面泄漏是否让抽取器过度声称」 | ✅ **有效**（not_generated +6 就是这个信号） |
| 测「域外方向发现能力（recall）」 | ❌ **无效**（域外参考里的方向本就不该被提） |
| 测「status 判准率」 | ⚠️ 有限（status 分布变了，但不是能力变化） |
| 测「泄漏的价签（分数虚高多少）」 | ⚠️ 有限 —— 泄漏**不必然让分数虚高**，它让分数**方向错乱** |

**最后一条要写进报告**：我们此前假设「泄漏 → 分数虚高」，
**实测是「泄漏 → 分数方向错乱」**（多报 not_generated、少报 realized，两者部分抵消）。
**所以「泄漏的价钱」不宜只用分数差表述**（㉑-b 的 0.1915 / 0.2558），
**还必须给出错乱的方向构成**（本条）。

### ㉗-d 报告里必须成对呈现的两个数

> **闭卷**：抽取器 F1 = 0.6154（真实能力）
> **开卷**：抽取器 F1 = ？ + **错乱构成**（not_generated +6 / realized −4）
>

### ㉚-a ★★ 「排除性陈述」算不算「表达」（not_generated vs selection_failure 的边界）

**第四轮分片 0 提出的问题（成立）**：

> |---|---|
